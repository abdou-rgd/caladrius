# oracle/expected/data

What `crates/caladrius-project/tests/oracle_data.rs` expects of the reading of the files in
`oracle/data/` and `oracle/data/population/` (specs/data.md OD-01 to OD-05).

| Files | Kind | Written by |
| --- | --- | --- |
| `<case>.json` for the load cases | `data_load`: delimiter, columns and roles, notes, check codes, and the `records` of every subject (rows, doses, observations, covariates) | `oracle/scripts/data_population.R` |
| `refuse_*.json` | `data_refusal`: the code and the pieces of the sentence, the subjects affected and not, and the `unaffected_records` of the subjects the problem does not affect (OD-02: they still load) | `oracle/scripts/data_population.R` |
| `legacy_notes.json` | `legacy_notes`: what the importer before the brick gave for each profile-layout file (OD-03, DAT-LEG-02) | a throwaway test, see below; **not** generated by the script |

Regenerate everything but `legacy_notes.json` with
`Rscript oracle/scripts/data_population.R` from the repository root (the run is deterministic: two
runs give identical files).

## How `legacy_notes.json` was produced

It holds, for each of the 18 profile-layout load cases whose options are `{}`, the notes, the check
codes and the number of readings that the importer of commit `7304519` (the last commit before the
brick, `T-147: renumber sources ...`) gives with `CsvOptions::default()`. It was written once and is
not regenerated by any script of this directory, because the point of the file is that it does not
follow the importer. The steps, so that the file can be checked again:

1. Check out `7304519` (the importer is `crates/caladrius-project/src`), and put the `oracle/` tree and
   `crates/caladrius-project/tests/oracle_data.cases` of the commit that introduced this file next to
   it (the importer of `7304519` does not know them, it only reads them).
2. Add `crates/caladrius-project/tests/zz_dump.rs`, the code below, and run
   `cargo test -p caladrius-project --test zz_dump -- --nocapture`. It prints one line that starts with
   `@@`: the JSON of every case (file, delimiter, decimal comma, columns with role and unit, notes,
   the serialized `checks`, number of readings). Keep that line, without the `@@`, as `dump.json`.
3. Run the R step below. It keeps `file`, `notes` (as `notes_exact`) and the number of readings, and
   writes `checks_exact` as an empty list: in the dump of this commit the `checks` of all 18 readings
   are empty, so the empty list is what the importer gave. The roles and columns of the dump are not
   pinned by this file (the load cases pin them).
4. Delete `zz_dump.rs`. Neither the test nor the dump is kept in the repository.

The throwaway test, as it was run (the two empty macros stand in for the macros of `oracle_data.rs`
that `oracle_data.cases` calls):

```rust
use caladrius_project::{readings, CsvOptions};
use serde_json::{json, Value};
use std::path::PathBuf;

macro_rules! load_tests { ($($n:ident),* $(,)?) => {}; }
macro_rules! refusal_tests { ($($n:ident),* $(,)?) => {}; }
include!("oracle_data.cases");

#[test]
fn dump() {
    let root = PathBuf::from(env!("CARGO_MANIFEST_DIR")).join("../../oracle");
    let mut cases = serde_json::Map::new();
    for name in LOAD_CASES {
        let exp: Value = serde_json::from_str(
            &std::fs::read_to_string(root.join("expected/data").join(format!("{name}.json"))).unwrap(),
        )
        .unwrap();
        if exp["layout"] != "profile" || exp["options"] != json!({}) {
            continue;
        }
        let file = exp["file"].as_str().unwrap();
        let bytes = std::fs::read(root.join("data").join(file)).unwrap();
        let rs = readings(&bytes, &CsvOptions::default()).unwrap();
        let r = &rs[0];
        let v = serde_json::to_value(r).unwrap();
        let cols: Vec<Value> = r.table.columns.iter().map(|c| {
            let cv = serde_json::to_value(c).unwrap();
            json!({"name": cv["name"], "role": cv["role"], "unit": cv["unit"]})
        }).collect();
        cases.insert(name.to_string(), json!({
            "file": file,
            "delimiter": r.table.delimiter.to_string(),
            "decimal_comma": r.table.decimal_comma,
            "columns": cols,
            "notes": r.table.notes,
            "checks": v["checks"],
            "n_readings": rs.len(),
        }));
    }
    let out = json!({"cases": cases});
    println!("@@{}", serde_json::to_string(&out).unwrap());
}
```

The R step (R 4.5.2, jsonlite 2.0.0), run from the repository root:

```r
suppressPackageStartupMessages(library(jsonlite))
d <- fromJSON("dump.json", simplifyVector = FALSE)$cases
cases <- lapply(d, function(g) list(file = g$file,
  notes_exact = I(unlist(g$notes, use.names = FALSE) %||% character(0)),
  checks_exact = I(character(0)), readings = g$n_readings))
out <- list(schema = 1L, kind = "legacy_notes", pinned_from_commit = "7304519",
  how = "The notes, checks and number of readings that the importer of this commit gives for each profile-layout file with default options (default reading). Written once from a throwaway test; the rules DAT-LEG-02 and OD-03 say these must not change.",
  cases = cases)
txt <- toJSON(out, auto_unbox = TRUE, pretty = TRUE, null = "null")
con <- file("oracle/expected/data/legacy_notes.json", open = "wb")
writeLines(txt, con, sep = "\n", useBytes = TRUE)
close(con)
```

What the file does **not** pin: any sentence of a check (the 18 readings have no check), the NCA and fit
outputs, history entries and exported files. The byte-level comparison of the worksheets, the notes,
the checks and the outputs of today's build (DAT-LEG-02, OD-03) is the work of card T-150, which pins
them from the code before its first edit.
