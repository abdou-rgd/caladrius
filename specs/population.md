## 1. The model (card item 1)

### POP-MOD-01 The model
For subject i, observation j:

y_ij = ŷ_ij(η_i) + σ_ij(η_i)·ε_ij,  ε_ij independent standard normal, independent of η_i, η_i ~ N(0, Ω).

The structural model f is one of the single-dose models of `specs/models.md` (POP-MOD-04) with the dose, dose time and duration of subject i taken from the dataset (POP-DAT-01). The individual parameters are **log-normal on the typical value**: P_ik = θ_k·exp(η_ik) for every parameter k that carries a random effect, and P_ik = θ_k for the others. Consequences (D): θ_k is the median of the distribution of P_ik, not its mean (the mean is θ_k·exp(Ω_kk/2)); a parameter with a random effect must have θ_k > 0 and the domain of the structural parameter (MOD-GEN-04) is then respected by construction; the derivative of the prediction with respect to the random effect is G_ijk = (∂ŷ_ij/∂P_ik)·P_ik (the chain rule through the exponential, which makes the relative sensitivity the natural unit). The sources agree on the form of the model (a conditional Gaussian observation model and Gaussian random effects, S-56 and S-57 at abstract level, S-52 for the notation of the linearisation); the log-normal link is a choice of the card (`AGENTS.md` section 1).
- Status: `assumed`
- Sources: card T-162 item 1; S-56, S-57 (abstract level: the nonlinear mixed-effects model and its approximate likelihoods); S-52 (the notation y = f(θ, η) + h(θ, η, ε)); D (the median, the mean and the chain rule).

### POP-MOD-02 Which parameters may have no random effect
Every structural parameter may be declared with or without a random effect; a parameter without one has η = 0 for all subjects and is shared exactly. The user declares the set explicitly (`random_effects`: a list of parameter names); there is no silent default, because the choice changes the answer. Rules:
1. A parameter with a random effect must have a typical value θ_k > 0 (POP-MOD-01); an initial estimate or a bound that allows 0 is `InvalidOption`.
2. **The bioavailability F is never estimated and never has a random effect** (MOD-GEN-03: only F·D is observable; F stays fixed).
3. **The lag time `tlag` and the duration `dur` (the parameter T of the zero-order models) carry no random effect in v1.** Reason (D, and the structure of MOD-AB1-05 and MOD-AB0-02): the prediction is continuous but has a kink at t = tlag (and at the end of the input), so G_i has a jump there and an observation close to the kink makes the inner problem and the derivatives of POP-COV-02 unstable. The parameter itself may be estimated as a typical value shared by all subjects. A request for a random effect on `tlag` or `dur` is refused with `InvalidOption` naming the parameter (OP-08). **Decision taken meanwhile (2026-11-08), reversible by Abdou:** this rule stands as proposed; the refusal sentences are in POP-INN-03 (item 6).
4. At least one parameter must carry a random effect (q ≥ 1): with q = 0 the fit is a pooled fit of all subjects and belongs to `specs/fit.md`.
5. A random effect on a parameter that the chosen model does not have is `InvalidOption`, naming the parameter and the model.
6. The derived parameter k = CL/V is not a parameter for this purpose: the user gives the primary set of MOD-GEN-03 (V with CL) or V with k, and the random effects go on those that are given (one of the two sets; both is an error, as in MOD-GEN-03).
- Status: `assumed`
- Sources: design choice of this card; MOD-GEN-03, MOD-GEN-04 (parameters and domains); D (the kink and its effect on the derivatives).

### POP-MOD-03 The shape of Ω: diagonal by default, one full block as an option
**Proposal.** v1 offers two shapes: `diagonal` (the default; q independent random effects) and `block` (one full q × q covariance over all the random effects). Block structures over subsets (some effects correlated, others not) are `later`. Reasons: (1) clearance and volume are often correlated in real data, and forcing a diagonal Ω when they are is a known source of bias and of misleading shrinkage, so a block is needed for real use; (2) a full block costs q(q + 1)/2 parameters and needs more subjects, so the diagonal must stay the default; (3) both shapes are offered by the open tools used as second looks (`nlme` through `pdDiag` and `pdLogChol`, S-48; the others at summary level), so both can be tested against the oracle; (4) with the log-Cholesky parameterisation of POP-EST-01 the block costs almost no extra code over the diagonal. **Decision taken meanwhile (2026-11-08), reversible by Abdou (OP-01):** the block is in v1, as proposed; the oracle has block cases (`lin_q2_block`, `lin_q3_block`, `int_oral_prop_q2_block`, `nl_oral_q2_block`). A random effect that the user fixes to a variance of 0 is the same as declaring no random effect for that parameter (POP-MOD-02).
- Status: `assumed`
- Sources: design choice with the reasons above; S-48 (`pdDiag`, `pdLogChol`, read in full); S-44 (`saemixModel` covariance structure, summary only).

### POP-MOD-04 Structural models in v1
The population fit accepts the single-dose models of `specs/models.md` that have closed forms and closed-form derivatives: the six `pk1.*` ids (`pk1.iv_bolus`, `pk1.iv_infusion`, `pk1.oral_1`, `pk1.oral_1_lag`, `pk1.oral_0`, `pk1.oral_0_lag`) and the six `pk2.*` ids (the same six routes with two compartments), the latter **in the clearance parameterisation only** (clearance, central volume, intercompartmental clearance, peripheral volume: MOD-2C-02). Reason for the restriction (corrected after review): the clearance set and the micro-constant set are both four independent positive parameters, so the log-normal link of POP-MOD-01 would apply to either; the clearance set is kept because it is the default of the catalogue and of the fit (MOD-2C-02, MOD-2C-17), and because the typical values and the random effects are then on quantities with a direct reading. The macro set is the one that is constrained (the ordering α > β that MOD-2C-17 names, and its dose-dependent definition of a and b: MOD-2C-02), and a log-normal random effect on each of its entries does not respect that. Offering the micro set later is a small extension, not excluded by a constraint. The three-compartment models (`pk3.*`) are **not in v1 for a reason about this branch, not about the models**: at the base of this branch (f9b0f33) the section on three compartments of `specs/models.md` still carries status `later` (MOD-LT-01); a specification of those models (T-140) and an engine (T-144) exist on the branch `iter3/pk3`, which is not on this base, and no population oracle covers them. Taking them into the population fit is a decision for after that branch is merged and after the population oracle exists (a card to write). Michaelis-Menten elimination (MOD-LT-02) is `later`. The derivatives ∂ŷ/∂P come from the closed forms of FIT-JAC-01 to 03 (the same functions as the individual fit).
- Status: `assumed`
- Sources: design choice; MOD-GEN-05 (ids), MOD-2C-02, MOD-2C-17 (the clearance set is the default; the macro set is the constrained one), MOD-LT-01 (status `later` at the base f9b0f33); FIT-JAC-01 to 03; the state of the branches named by the orchestrator (T-140, T-144 on `iter3/pk3`, not read here).

### POP-MOD-05 A test-only model with the identity link
For the exact cases of POP-ORA-01 the core of the objective takes, besides the user-facing models, a **test-only structural model with the identity link and a prediction linear in η**: P_i = θ + η_i (no exponential), ŷ_ij = a_ij(θ) + Σ_k z_ijk(θ)·η_ik, with a and z given by the test (for the worked example PX1: a_ij = θ_1 + θ_2·t_ij, z_ij = 1). It is not offered to users, is not in the model catalogue of MOD-GEN-05, and exists so that the Laplace-type objective can be checked where it is exact without any population software. Where it lives (a test model in `caladrius-testkit` or a feature of the crate) is the engine card's choice; the requirement is that the same objective code runs it.

**Request format (decision taken meanwhile, 2026-11-08, reversible by Abdou; it is the format the oracle already uses).** The request names `model = "identity_linear"`. The typical values are the keys `theta1` and `theta2` of `initial`, and the mean is a_ij = θ_1 + θ_2·t_ij, where t_ij is the time since the dose of the subject (the dose row's time; POP-DAT-01). The design of η is given by `model_options.z_powers`: a list of q non-negative integers, in the order of `random_effects`, and Z_ijk = t_ij^(z_powers[k]) with the same t_ij (so `[0]` is a random intercept, `[0, 1]` an intercept and a slope, `[0, 1, 2]` adds a curvature). The names in `random_effects` are free labels for this model (the oracle uses "intercept", "slope", "curvature"); they do not refer to a structural parameter, and POP-MOD-02 rules 1 and 5 do not apply to them (the link is the identity, so a typical value of 0 or less is allowed). The error model, Ω, the shape and the options are given as for any other model.
- Status: `assumed`
- Sources: design choice; D (POP-ORA-01 needs a model linear in η, and `P = θ·exp(η)` is not linear in η).

## 2. The residual error (card item 2)

### POP-ERR-01 Error models, evaluated on the individual prediction
The error models are those of FIT-ML-02 and FIT-ML-03, with the same ids and the same meaning: `additive` (σ = a), `proportional` (σ = b·|ŷ|), `combined` (σ = √(a² + b²·ŷ²), the variance sum, the default combined form) and `combined_sd` (σ = a + b·|ŷ|). The prediction in the formula is **the individual prediction ŷ_ij(η̂_i)**: this is the interaction, so the standard deviation of an observation moves with the random effect of its subject, and in the inner problem σ_ij is a function of η (POP-INN-01). The error parameters ξ are shared by all subjects, there is one error model per run and one endpoint (DAT-CMT-01), and they are moved on the variance scale of FIT-ML-05 (A = a², B = b², bound 0, active-set rule; `combined_sd` moves a and b themselves). The user must name `error_model`; there is no default (FIT-ML-01). An error model that is not `additive` on a prediction of 0 is the case FIT-ML-13c and FIT-ML-14b, handled in POP-INN-03.
- Status: `documented, untested`
- Sources: FIT-ML-02, -03, -05 (S-39, S-43); S-52 (the dependence of the variance on η̂ in the FOCE covariance); D.

### POP-ERR-02 The derivative of the error model with respect to η
Needed by the inner problem (POP-INN-02) and by POP-OBJ-04. With s = σ²: ∂σ/∂η_k = (∂σ/∂ŷ)·G_k, and ∂ ln σ/∂ŷ is the column of FIT-ML-06:

| error model | ∂ ln σ/∂ŷ | ∂σ²/∂ŷ |
|---|---|---|
| `additive` | 0 | 0 |
| `proportional` | 1/ŷ | 2b²·ŷ |
| `combined` | B·ŷ/σ² (B = b²) | 2b²·ŷ |
| `combined_sd` | b·sgn(ŷ)/σ | 2σ·b·sgn(ŷ) |

(∂σ²/∂ŷ = 2σ²·∂ ln σ/∂ŷ in every row.) With `additive` the variance does not depend on η, which is why the exact cases of POP-ORA-01 use it.
- Status: `documented, untested`
- Sources: FIT-ML-06 (the table of ∂ ln σ/∂ŷ, D); D (the chain rule and σ² = σ·σ).

## 3. The objective (card item 3)

### POP-OBJ-01 What is approximated
For subject i the marginal likelihood is

L_i = ∫ Π_j N(y_ij; ŷ_ij(η), σ_ij(η)²) · N(η; 0, Ω) dη,

an integral over η ∈ R^q that has no closed form for a model nonlinear in η. The population objective is OFV = −2·Σ_i ln L_i (subjects are independent given θ, Ω, ξ). FOCEI replaces each integral by an approximation built from the conditional mode η̂_i and first derivatives (POP-OBJ-02); FO replaces η̂_i by 0 (POP-OBJ-03). Neither is exact for a model nonlinear in η; the gap is not small (section 10, PX2: 0.09 to 0.3 on a total of about −14.2 for four subjects), which is why the exact cases of POP-ORA-01 are the first oracle and why the engine must never be tested against the exact marginal in the nonlinear case with a tight tolerance.
- Status: `documented, untested`
- Sources: S-56, S-57, S-55 (abstract level: the likelihood of a nonlinear mixed-effects model has no closed form and is approximated around the conditional modes); D (the integral); H32 (R: the integral computed by adaptive Gauss-Hermite quadrature, 60 and 40 nodes per dimension agree to 2e-9, example PX2).

### POP-OBJ-02 The FOCEI objective, per subject
At η̂_i (POP-INN-01), with ŷ_i = ŷ_i(η̂_i), G = G_i(η̂_i), σ̂_ij = g(ŷ_ij; ξ):

- E_i = ŷ_i − G·η̂_i (the first-order expansion of the prediction at η̂_i, evaluated at η = 0),
- C_i = G·Ω·Gᵀ + diag(σ̂_i1², ..., σ̂_in²) (the covariance of y_i under the same expansion; the variances are those of the individual prediction, which is the interaction),
- **OFV_i = n_i·ln(2π) + ln|C_i| + (y_i − E_i)ᵀ·C_i⁻¹·(y_i − E_i)**,
- OFV = Σ_i OFV_i, summed in subject order (POP-DET-01).

This is the objective of the FOCE method written from the linearisation of Lindstrom and Bates, read here as the −2 log-likelihood of the Gaussian model y_i ≈ E_i + G·η + e with e ~ N(0, diag σ̂²) and η ~ N(0, Ω): the two terms are the log-determinant and the squared Mahalanobis distance of the same Cov. The S-52 slides write it, for FOCE, as the sum of ln Cov and the squared standardised distance with exactly this E and this Cov, with the derivative of the prediction at η̂_i and the derivative of the error model at ε = 0. What this rule adds is the interaction (the error model derivative taken at the individual prediction) and the constant n_i·ln(2π) (POP-OBJ-05). C_i is positive definite whenever Ω is and every σ̂_ij > 0 (D), so its Cholesky factor exists; the engine computes ln|C_i| and the distance from that factor (n_i × n_i, small), never from an explicit inverse. When the structural model is linear in η and σ does not depend on η, E_i = ŷ_i(0) and C_i does not depend on η̂_i, and OFV_i is the exact −2 ln L_i (POP-ORA-01). The identity-link test model of POP-MOD-05 uses the same formulas with G = Z.

A Laplace expression with the Hessian of the joint log-density in place of the linearisation gives a different number when the error variance depends on η, and in one of its three forms also for a model nonlinear in η (POP-OBJ-04, which states the exact identity and its condition). Which of them a reference tool computes is open item OP-02; this rule is the default because it is the one the cited slides write for the FOCE objective.
- Status: `documented, untested`
- Sources: S-52 (the FOCE expectation and covariance and the objective as the sum of ln Cov and the squared standardised distance; slides, read in full, equations garbled by the text extraction, so the symbols of the objective were read from the layout and checked by H32); S-55, S-58 (Lindstrom and Bates linearisation and the family of FO, FOCE, FOCEI methods, abstract level); D (the Gaussian density, the extension to the interaction); H32, H33 (R: the identity of the linearised form with the exact marginal for a model linear in η, example PX1, and its value for a nonlinear model, example PX2).

### POP-OBJ-03 The FO objective: the same function at η = 0
FO is the objective of POP-OBJ-02 evaluated **with η̂_i := 0 for every subject**, with no inner problem:

- E_i = ŷ_i(0) (the population prediction, PRED),
- G_i⁰ = G_i(0), σ⁰_ij = g(ŷ_ij(0); ξ), C_i = G_i⁰·Ω·G_i⁰ᵀ + diag(σ⁰_ij²),
- OFV_i^FO = n_i·ln(2π) + ln|C_i| + (y_i − ŷ_i(0))ᵀ·C_i⁻¹·(y_i − ŷ_i(0)).

There is no interaction in FO: the error variances are those of the population prediction. This is the case "η = 0" of the card. FO and FOCEI coincide when the model is linear in η and σ does not depend on η (POP-ORA-01), and differ otherwise (PX2). The FO objective is what the S-52 slides write for the FO method. FO is offered as the option `method = fo` (FOCEI is `foce_i`, the default; plain FOCE is `foce`, POP-OBJ-06); the FO fit has no η̂_i, so the EBE-based diagnostics (IPRED, IWRES, CWRES, shrinkage) are not defined after an FO fit in v1 and are NC with the reason `fo` (computing them after an FO fit by a post-hoc step is `later`; this is the first part of OP-14, **decision taken meanwhile (2026-11-08), reversible by Abdou**: the second part, plain FOCE, is in v1).
- Status: `documented, untested`
- Sources: S-52 (the FO expectation f(θ, 0), the FO covariance and the FO objective); D (the statement that POP-OBJ-02 at η̂ = 0 is the FO formula); H33 (R: the FO value of PX2 and of PX1).

### POP-OBJ-04 Other objective forms, named for the oracle
Three further forms are written here so that the oracle can recognise the one a reference tool computes (OP-02); none is required of the engine in v1, and the choice between them is not a tolerance but a method difference (`AGENTS.md` section 5, `specs/differences.md`). Let h_i(η) = Σ_j [ln σ_ij(η)² + r_ij(η)²/σ_ij(η)²] + ηᵀΩ⁻¹η, so that η̂_i = argmin h_i (POP-INN-01). The Laplace approximation of the integral of POP-OBJ-01 is (D: expand h_i to second order at η̂_i; the q·ln(2π) of the prior cancels against the Gaussian integral)

OFV_i^Lap = n_i·ln(2π) + h_i(η̂_i) + ln|Ω| + ln|½·∇²h_i(η̂_i)| = n_i·ln(2π) + ℓ_i(η̂_i) + η̂_iᵀΩ⁻¹η̂_i + ln|I_q + Ω·A_i|,

with ℓ_i = Σ_j[ln σ² + r²/σ²] and A_i a q × q matrix that stands for ½·∇²ℓ_i(η̂_i): (a) `laplace_full`: A_i the exact half-Hessian (second derivatives of the model needed); (b) `laplace_expected`: A_i = Σ_j [G_j·G_jᵀ/σ_j² + ½·(∇σ_j²)(∇σ_j²)ᵀ/σ_j⁴] (the expected information of the Gaussian observation, using E r² = σ²; it is the matrix 𝒥ᵀ𝒥 of POP-INN-02 without its prior rows); (c) `laplace_no_variance`: the first term only. All three equal the exact value for a model linear in η with σ independent of η. **Identity (added after review, checked by the reader).** Let ρ = y − E = r̂ + G·η̂ (the vector of POP-OBJ-02), Σ = diag(σ̂²) and A = GᵀΣ⁻¹G. By the Woodbury identity ρᵀC⁻¹ρ = min over η of [(r̂ + G(η̂ − η))ᵀΣ⁻¹(r̂ + G(η̂ − η)) + ηᵀΩ⁻¹η], and by the determinant lemma ln|C| = ln|Σ| + ln|I + Ω·A|. The minimiser is η̂ exactly when GᵀΣ⁻¹r̂ = Ω⁻¹η̂, which is the stationarity of h_i **when ∂σ/∂η = 0**. Then OFV_i of POP-OBJ-02 equals OFV_i^Lap with A_i = A, that is `linearised` = `laplace_no_variance` = `laplace_expected`, **for any model, however nonlinear in η, whenever σ does not depend on η** (additive error, or an error whose σ is held at fixed values while the mode is found). Only `laplace_full` differs then (it carries the term in the second derivatives of the model, which is nonzero for a model nonlinear in η), and so do FO and the exact marginal. **With the interaction (σ depending on η through the prediction) the identity does not hold**, the three split, and PX2 shows by how much. Checked by the reader (H35): in double precision on the data of PX2 with additive σ = 0.2 the first two agree on the four subjects to about 4e-15, and with proportional error and σ frozen at ŷ(η̂) (mode recomputed) to about 4e-14; with the interaction they differ by 0.004 to 0.028 per subject; at 256 bits on a one-random-effect case with a model nonlinear in η (script described in section 10, PX5) the two agree to 1.4e-76, about two units of the last bit, and `laplace_full` differs by 0.0144. No source read gives the formula that a given open tool uses; the foceiControl page of S-49 lists two inner curvature choices (`focei`, `conditional`) without defining them, which shows that the choice exists in the reference tool.
- Status: `documented, untested` (the forms are derived and the identity is checked numerically; which one the reference computes is not known)

### POP-OBJ-05 The OFV convention is named in every answer
The constant is the whole difference between two conventions, and both are valid; a value without its convention cannot be compared with another (the value can be negative, FIT-ML-04). Caladrius's rule, with its reason: **every command that returns an OFV, an AIC or a BIC returns, in the same answer, the field `ofv_convention`, and a value is never shown without it.** Two conventions exist:

- `full`: OFV as defined in POP-OBJ-02 and POP-OBJ-03, constant kept, i.e. −2 times the log of the (approximate) marginal density of the observations. **Default.** Reason: it is the one that keeps the meaning of FIT-ML-04 (the true Gaussian −2LL) and it is what the exact cases of POP-ORA-01 compute without a population tool.
- `no_2pi`: OFV_no_2pi = OFV_full − N·ln(2π), N the number of observations used (all subjects). The open reference tool's objective omits "the 2π constant" and the tool has an option, `adjLik`, that adds it to the likelihood it reports; on the page read (S-49, `nlmixr2est` 7.2.1) `adjLik` is TRUE by default and the objective function value itself is not adjusted. Whether that constant is exactly N·ln(2π) in every model, and whether it also contains a per-subject term, is not stated by the page and is open item OP-03, to be settled by the oracle: record the objective value (constant omitted) and −2 times the log-likelihood with `adjLik = TRUE`, and test that their difference is N·ln(2π) (POP-ORA-02).

Properties: the minimiser is the same in both; differences of OFV between fits of the same observations are the same; AIC and BIC are built from the OFV of the convention stated and carry it (POP-DIA-04); comparing OFV, AIC or BIC across two answers with different `ofv_convention`, or with different N, is refused by any command that compares (the engine does not subtract values of two conventions silently). The convention is part of the answer and therefore part of its seal (`AGENTS.md` rule 10). It is chosen by the option `ofv_convention` (`full` or `no_2pi`) and recorded in the result and in the trace.

**Decision taken meanwhile (2026-11-08), reversible by Abdou (OP-03):** the proposal stands: `full` is the default and `no_2pi` is the second convention. The measurement of the reference's constant is not part of this decision; it stays in POP-ORA-02.
- Status: `assumed`
- Sources: design choice with the reasons above; FIT-ML-04 (the constant and its consequences), FIT-ML-16 and OF-20 (a value of another program cannot be compared without checking the constant); S-49 (`adjLik`: the open tool omits a 2π constant by default); D (the difference N·ln(2π) and its cancellation in differences).

### POP-OBJ-06 Plain FOCE (no interaction): the variance frozen at the population prediction
**Decision taken meanwhile (2026-11-08), reversible by Abdou (OP-14):** FOCE without interaction is in v1, as the option `method = foce`. The values of `method` are therefore `foce_i` (the default), `foce` and `fo`.

**Where the variance is evaluated (T-152 question 1, settled from open sources).** The documentation of the open tool used as a second look (S-80) describes two conventions for FOCE without interaction. In its default one the residual variance is **frozen at the population prediction, the prediction at η = 0, and held constant across the inner optimisation**; its release notes (S-81), a comment in its source (S-82) and a 2026 article on an open-source re-implementation (S-83) say the same. The other convention evaluates the variance live at the current conditional η and drops the variance derivatives; it is the convention of that tool up to its version 6.0.1 and is kept there as an option. Caladrius adopts the first (the population prediction), for three reasons: it is the default of the only open implementation read, it is what the later versions of that implementation changed to, and its inner problem is a plain weighted least squares plus the prior penalty, which the exact identity of POP-OBJ-04 checks (POP-ORA-01 (c)). Where the literature calls the method without interaction limited to an additive error (S-84) or problematic with heteroscedastic errors (S-83), the statement is consistent with this definition (below).

**Definition.** For subject i, with σ⁰_ij = g(ŷ_ij(0); ξ) (the same quantity as in POP-OBJ-03; it depends on θ and ξ and not on η):

- the inner problem is h⁰_i(η) = Σ_j r_ij(η)²/(σ⁰_ij)² + ηᵀ·Ω⁻¹·η, with the minimiser η̂_i. Its stacked system is that of POP-INN-02 with the second block of rows removed (l_jk = 0, u_jk = G_jk/σ⁰_j): n_i + q rows, 𝒥ᵀ𝒥 = Σ_j u_j·u_jᵀ + Ω⁻¹. Everything else of POP-INN-02 and POP-INN-03 applies unchanged (the start, the line search, the polish, the refusals);
- E_i = ŷ_i(η̂_i) − G_i(η̂_i)·η̂_i and C_i = G_i(η̂_i)·Ω·G_i(η̂_i)ᵀ + diag((σ⁰_ij)²): the variances are those of the population prediction, not those of the individual prediction. **What was read and what is inferred:** the text of `foceiControl` (S-80) speaks only of the residual variance in the inner objective, which is the first bullet. That the same frozen σ⁰ enters C_i in the outer objective is the reader's inference, not read in a source: it is the definition that makes OFV^FOCE the `linearised` form of POP-OBJ-04 at a fixed σ and makes it equal to OFV^FOCEI for an additive error (consequence 2 below). It is `assumed`;
- **OFV_i^FOCE = n_i·ln(2π) + ln|C_i| + (y_i − E_i)ᵀ·C_i⁻¹·(y_i − E_i)**, summed in subject order, with the conventions of POP-OBJ-05 and the diagnostics of section 6 (CWRES uses the E_i and C_i of this definition; IWRES is unchanged, POP-DIA-02).

Consequences (D, checked by H36 and by the identity of POP-OBJ-04): (1) OFV_i^FOCE is the `laplace_no_variance` and `laplace_expected` form with σ held at σ⁰, which is `linearised` of POP-OBJ-04 for that fixed σ; (2) **with an `additive` error σ⁰ does not depend on η and OFV^FOCE equals OFV^FOCEI exactly** (the same function, the same η̂_i; this is the reading of S-84); (3) with `proportional`, `combined` or `combined_sd` the two differ, and plain FOCE is the cruder one: on the data of example PX2 (proportional error, four subjects) the total is -15.7471 with σ frozen at the population prediction against -14.1419 for FOCEI, a gap of 1.6052 (PX6); (4) FO is the same formula evaluated at η̂ = 0 (POP-OBJ-03), so the three methods are one family. The user is warned in the documentation of the option that with a proportional or combined error `foce` and `foce_i` give different objective values and different estimates, and that the literature recommends the interaction in that case (S-83).

**To be measured when the open tool is installed (Q-021).** The value -15.7471 above was confirmed against a figure seen in a search summary after the answer was known, so the confirmation is weaker than an independent one. When nlmixr2est is installed, the OFV at the PX2 parameters with `foce = "nonmem"` must be -15.7471 (the argument value of the open tool, S-80; not a use of any vendor documentation); `foce = "foce+"` and `interaction = TRUE` are the comparison runs (they should give the other figures of PX6, which is the correspondence marked `assumed` below). Until then the figure is the reader's computation (H36), not a measurement of that tool.

**The variance frozen at the mode is not an engine method.** The value of the objective with σ frozen at its value at the mode, the fixed point of "find the mode for a given σ, then reset σ to its value there", is a different function: on PX2 it is -14.0214, not -15.7471 (PX6). It is the stationary point of the other convention described above (the live variance without the variance derivatives has the same stationary point; this is the reader's inference, not read in a source, and it is `assumed`). The oracle's `frz_*_mode` cases keep their use as identity checks of POP-OBJ-04 in the testkit; its `frz_*_pred0` cases are the exact reference of `method = foce` (POP-ORA-01).

## 3b. The inner problem: the empirical Bayes estimate

### POP-INN-01 The inner problem
For each subject, at the current (θ, Ω, ξ):

η̂_i = argmin_η h_i(η),  h_i(η) = Σ_j [ ln σ_ij(η)² + r_ij(η)²/σ_ij(η)² ] + ηᵀ·Ω⁻¹·η.

This is the extended-least-squares objective of the individual profile (FIT-ML-04 without its constant) plus the prior penalty ηᵀΩ⁻¹η, and η̂_i is the mode of the density of η given y_i (D: the negative log of the joint density up to constants). With the interaction the variance depends on η and the first sum includes ln σ²; without it (σ held at ŷ(0)) the problem would be a weighted least squares plus the penalty, which is not what FOCEI means (it is the inner problem of the method `foce`, POP-OBJ-06). The problem has q unknowns and no bounds. It is solved separately for each subject, from data of that subject only (POP-DET-02).
- Status: `documented, untested`
- Sources: D (Bayes' rule for the density of η; FIT-ML-04 for the individual part); S-52 (the conditional estimates η̂_i as the point of expansion); H32 (R: the mode found by BFGS then Newton polish, gradient about 1e-5 at the printed digits on PX2).

### POP-INN-02 How the inner problem reuses `caladrius-fit`
The individual maximum-likelihood fit of FIT-ML-06 to FIT-ML-08 is a Gauss-Newton (Fisher-scoring) iteration on a stacked system of residual rows. The inner problem is the same system with **ζ replaced by η and one block of prior rows added**. Write Ω = L·Lᵀ (Cholesky, from the current Ω) and, for each observation, u_jk = G_jk/σ_j, l_jk = (∂ ln σ_j/∂ŷ_j)·G_jk (POP-ERR-02), z_j = r_j/σ_j. The stacked system has 2n_i + q rows:

- residual vector R: z_j; then (z_j² − 1)/√2; then **−L⁻¹η** (the prior rows),
- matrix 𝒥: rows u_j; rows √2·l_j; rows **L⁻¹** (q × q).

Then 𝒥ᵀR is half the negative gradient of h_i exactly (D: the first two blocks are g of FIT-ML-06, and −Ω⁻¹η is half the negative gradient of ηᵀΩ⁻¹η), and 𝒥ᵀ𝒥 = Σ_j (u_j·u_jᵀ + 2·l_j·l_jᵀ) + Ω⁻¹, the expected information of the subject given η plus the prior precision. The fixed point of the scoring step is therefore the exact mode, whatever approximation 𝒥ᵀ𝒥 makes of the curvature. All of FIT-ALG-02 to FIT-ALG-04 applies unchanged: column scaling, QR (Householder) of the stacked matrix, step halving down to the same floor (FIT-ML-07), Levenberg damping on failure, and the stopping test of FIT-ML-08, the **Newton decrement** Δ_i = gᵀ(𝒥ᵀ𝒥)⁻¹g ≤ ε_in, absolute. ε_in is the default ε of FIT-ML-08 (the value of that rule) for an evaluation of the OFV that is not part of a difference quotient; **every inner solve whose η̂_i or OFV_i is returned (the outer objective, the points of a difference quotient of POP-EST-03 and POP-COV-02, the confirmation Hessian, every `evaluate_only` answer) is run to the Newton-polish floor of FIT-ML-08, whatever ε_in says; in practice every inner solve is polished, and the engine never stops early on one point of a difference and not on the other**. The Newton decrement is taken in this convention (the one of H37): g = 𝒥ᵀR, half the negative gradient of h_i (h_i without the ln 2π term); M = 𝒥ᵀ𝒥, half the expected Hessian, the expected information plus the prior precision; Δ_i = gᵀM⁻¹g = g·δ for the scoring step δ = M⁻¹g. With the full-scale gradient and Hessian of h_i (twice g, twice M) the same quantity is 2Δ_i, and with the observed Hessian in place of M it is another number; a value of ε_in is meaningful only with its convention. Reason (added after review, D): OFV_i is not stationary in η̂_i, unlike h_i (the envelope argument applies to h_i, not to the linearised OFV_i, which depends on η̂_i through E, G and σ̂), so an error δη in the inner solve enters OFV_i at first order; if the number of inner iterations differs between φ and φ ± h, the difference quotient jumps and the gradient carries noise of order δη/h. Differences from the individual fit: nothing is bounded, no error parameter moves, the derivatives are with respect to η (the chain rule of POP-MOD-01), and the output of the last iteration includes ln|𝒥ᵀ𝒥| (twice the sum of the logarithms of the diagonal of the R factor of the unscaled stacked matrix) for the forms of POP-OBJ-04 that use it. The Newton polish with the observed information of FIT-ML-08 is applied as stated above.

**What is reused and what is new (corrected after review; the code was read at the base f9b0f33).** The pieces are reusable as they are: `linalg::least_squares` (the QR solve), `engine::damped`, `ErrorModel::sigma` and `ErrorModel::dln_sigma_dyhat` of `crates/caladrius-fit/src/objective.rs`. The stacked system itself is not: `ml::system()` in `crates/caladrius-fit/src/ml.rs` is private, takes the Jacobian as columns of the structural parameters, builds columns for the error parameters ξ and has no hook for appended rows. The inner problem therefore needs a **new module beside `ml.rs`** with its own builder of the system: the n_i × q Jacobian G by the chain rule of POP-MOD-01, the two observation blocks of rows, q prior rows, and no ξ columns.

**Start.** The first evaluation of a subject starts at η = 0, the prior mean. **Every later evaluation, including the 2p points of a difference quotient, starts from the η̂_i of the last accepted outer iterate of that subject, and from nothing else** (changed after review: a start taken from "the nearest earlier evaluation" depends on the order in which difference points finish when they run on several threads, POP-DET-02). If the solve from that start fails the engine goes down the start ladder below before giving up. The start rule is part of the algorithm and is a function of the subject's own accepted history only. A subject whose h_i has several minima may be found at either; this is not detected, as FIT-OBJ-01 for the individual fit.

**Where the objective curves the wrong way (T-152 question 12; hand check H37).** With a large ω and a combined error, h_i can have a negative observed second derivative on stretches away from its mode, so a Newton step on the observed Hessian there is not a descent step. On the oracle case `int_iv_comb_q1_large` (`pk1.iv_bolus`, `combined` with a = 0.05 and b = 0.15, one random effect on `cl`, Ω = 0.5, three subjects) each subject has exactly one stationary point on [-6, 6] (η̂ = 0.517, -0.429, 0.478), and the observed second derivative of h is negative on stretches of that interval: for subject S3 on -2.451 to 0.05, 2.484 to 2.745 and 3.731 to 5.456, and at η = 0 it is -11.2441 for S3 and -15.6181 for S1 (it is +497.6584 for S2), while twice the expected information plus the prior precision is 176.0025 for all three. The inner solver must satisfy, whatever the code does:
1. **The step is a descent direction wherever the objective is defined.** It comes from the scoring matrix 𝒥ᵀ𝒥, which is the expected information plus the prior precision and is positive definite for every η (Ω⁻¹ is), and never from the observed Hessian away from the mode. A step taken from a matrix that is not positive definite is not allowed.
2. **A line search protects every step.** The step is accepted only if it lowers h_i (FIT-ML-07: halve while the trial does not lower the objective); otherwise it is halved, from ν = 1 down to 2⁻¹⁰ (FIT-ML-07), then the Levenberg damping of FIT-ALG-04 is raised. A trial for which h_i is not finite, or σ is not positive, is a rejected trial (POP-INN-03, item 2).
3. **The start ladder.** The solve begins at the warm start (the last accepted η̂_i of the subject, or 0 for the first evaluation). If it fails it is restarted from 0, then from ±2 and ±4 on each coordinate k in turn (k in the order of `random_effects`, first +2, then -2, then +4, then -4, the other coordinates at 0), and the first start that converges is used. η is on the log scale of POP-MOD-01, so absolute starts of this size are meaningful (they multiply the typical value by exp(±2) and exp(±4)). If every start fails, the outcome is `inner_failed` at the starting parameters, and a rejected trial later (POP-INN-03, item 4). The evidence for this ladder is on one random effect (q = 1); for q > 1 it is a design choice and is `assumed`.
4. **What counts as converged.** The Newton decrement Δ_i of FIT-ML-08 is at most ε_in at a finite h_i. That test is on the scoring decrement (convention above). **Every inner solve whose η̂_i or OFV_i is returned is then polished; in practice every inner solve is polished.** The reason is that OFV_i is not stationary in η (the slope is up to 37.4 on the oracle cases, Q-026; that figure is the board's, not measured here), so an error of 6e-7 in η̂ moves OFV_i by about 2e-5 (the product of the two), far above the tolerance `POP_OFV`; only the polish brings the error to 1e-12 and below (H37). The Newton polish of FIT-ML-08 follows: Newton steps on the observed information (central differences of the analytic score), each accepted only if h_i does not increase and Δ_i strictly decreases (the rule of FIT-ML-08), **with one condition added for the inner problem: the observed Hessian must be positive definite at the point**; at most 12 steps, to Δ_i ≤ 1e-26. A step whose conditions fail is not taken and the polish stops, so it cannot move an η̂ away from the mode.
5. **No search for another minimum.** If h_i has several local minima the solver reports the one it reaches from the ladder; the case is not detected (FIT-OBJ-01).

What was measured (H37, double precision, the scoring step with halving, Δ ≤ 1e-10): from the starts 0, -4, -2, 2 and 4 each subject converged in 7 to 10 iterations with no halving to the same value of h, and the error of η̂ against the 256-bit mode of the oracle file was 8.31e-7, 3.04e-7 and 1.75e-7 (S1, S2, S3) at that stop (Δ in the convention above, M the expected information plus the prior precision; a review that took another matrix or scale for Δ found 8.5e-8 for S1, because the iterate at which Δ first falls below 1e-10 depends on the convention, so the figure is a measurement of that convention and not a property of the problem) and 8.99e-13, 1.96e-13 and 5.48e-14 after one polish step. Plain Newton on the observed information with no safeguard also reached the mode from the same starts (7 to 26 iterations); that is a property of this case, not a guarantee, and rule 1 does not rely on it. The test of the engine for this requirement is the oracle case `int_iv_comb_q1_large` itself (the objective to the tolerance of Q-026) together with a start at η = 0 on S3.
- Status: `documented, untested` for the system, the scoring step and the polish; `assumed` for the order of the start ladder, its extension beyond q = 1, the added positive-definiteness condition of the polish and the clause on the test
- Sources: D (the stacked system, the prior rows and their sign; 𝒥ᵀ𝒥 as information plus precision; the fixed point); H37 (R: the curvature of h on `int_iv_comb_q1_large`, the scoring runs); FIT-ML-06 to -08, FIT-ALG-02 to -04 (S-23 to S-26, the machinery reused); H33 (R: the scoring system on the 4 subjects of PX2 reaches the same modes as BFGS plus Newton polish).

## 4. The estimation (card item 4)

### POP-EST-01 What the outer optimiser moves
The outer vector φ holds, in this order:

1. **Typical values.** For every θ_k that carries a random effect: ln θ_k. For a θ_k without a random effect: θ_k itself on its natural scale with its own bounds (FIT-BND-01, 03), because it may legitimately be 0 (`tlag`) or sit on a bound.
2. **Ω** (the free entries of Ω after the user's fixed ones): the **log-Cholesky** parameters. For `diagonal`: λ_k = ln ω_k (the logarithm of the standard deviation). For `block`: Ω = L·Lᵀ with L lower triangular, L_kk = exp(λ_kk) and the below-diagonal entries of L free, which is the same parameterisation as the one `nlme` documents for a general positive-definite matrix (S-48: the logarithms of the diagonal of the Cholesky factor, followed by the off-diagonal part of the triangle; its diagonal form is the logarithm of the square roots of the variances). Positive definiteness holds for every φ, with no constraint.
3. **Error parameters ξ.** On the variance scale of FIT-ML-05 (A = a², B = b², bound 0), not on a log scale. Reason (the argument of FIT-ML-05, unchanged): the boundary solution of a combined model must be reachable exactly; a log scale stalls before it.

Why log for θ and for Ω but not for ξ: a typical value with a random effect cannot be 0 or negative, and the objective is smooth and scale-free in its logarithm (the parameters of the models range over decades); a random-effect standard deviation tends to 0 only when the data cannot identify it, which is a diagnosis (POP-EST-04), not a solution to reach. The price is that ω_k = 0 is not reachable: a variance that wants to collapse makes the log scale drift (the information in ln ω_k tends to 0) and the outer stop test fires before 0; the result carries the flag `omega_collapse` (POP-EST-04). The variance scale with bound 0 (as for ξ) was not chosen for Ω because a variance at 0 removes a dimension from the inner problem, so the dimension of η would change during the fit.
- Status: `assumed`
- Sources: S-48 (`pdLogChol` and `pdDiag`, read in full); FIT-ML-05 (error parameters); D (smoothness and positivity); design choice.

### POP-EST-02 Bounds and fixed parameters
The bounds of FIT-BND-01 and FIT-BND-03 apply to every typical value, converted to the log scale for those with a random effect (a lower bound ≤ 0 on such a θ is replaced by the open domain θ > 0). **Decision taken meanwhile (2026-11-08), reversible by Abdou: the request key is `fixed`, the name the oracle rows already use (`pr1_lag_fixed_at_first_time`: `"fixed": {"tlag": 0.5}`), and not `fix`; the bounds are the key `bounds` (POP-API-01 item 12).** A **fixed** parameter (the user gives `fixed`) leaves φ: θ_k or an error parameter can be fixed, and so can Ω in two cases only: a **diagonal** Ω (a standard deviation ω_k, which is one coordinate of φ) or a **whole block** (all of its log-Cholesky entries together). Fixing a single element of a block (one variance or one covariance) is `later`: under the log-Cholesky parameterisation an element of Ω is a function of several entries of L, so fixing it is a nonlinear constraint that the active set of FIT-BND-01 cannot express (changed after review). A fixed ω_k = 0 is the same as no random effect for that parameter (POP-MOD-02). A parameter held on a bound at the end is reported with the status `at_bound` as in FIT-ML-15, its standard error is NC with that reason, and the others are conditional on it (FIT-BND-02). The error parameters have the lower bound 0 of FIT-ML-05. Ω has no bound: positive definiteness is built in.
- Status: `assumed`
- Sources: FIT-BND-01, -02, -03; FIT-ML-05, -15; design choice.

### POP-EST-03 The outer optimiser and its stopping rules
The outer problem is the minimisation of OFV(φ) = Σ_i OFV_i(φ) (POP-OBJ-02 or -03) over φ, each evaluation running the m inner problems of POP-INN-02. FO has no inner problem and is the same outer problem with cheaper evaluations.

**Algorithm.** A quasi-Newton (BFGS) iteration on φ, written in the engine (pure Rust, no external optimiser, `AGENTS.md` rule 10), with the active-set treatment of FIT-BND-01 for the variables on a bound, a backtracking step control like FIT-ML-07 (ν = 1 halved while the trial does not lower the OFV; a trial is rejected if any inner problem fails, if any OFV_i is not finite, or if a bound is violated; Levenberg-style damping does not apply here), and the gradient of the OFV by **central differences** of the OFV with a step proportional to max(|φ_j|, 1) (h, OP-11), each difference re-solving the inner problems **to the polish floor** (POP-INN-02: an inner error enters OFV_i at first order). Conditions on h, which only a value of OP-11 can satisfy together: h²·|∂³OFV/∂φ³| far below the gradient (truncation), and the inner error divided by h far below the gradient (noise); the confirmation Hessian has the same two conditions, with h² in the denominator of the noise term. The value of h is left to OP-11. The reference tool's outer optimiser is not fixed by the documentation read: on the page of S-49 (`nlmixr2est` 7.2.1) the signature default is `outerOpt = "bobyqa"`, the text ties the default to a `fast` option (`"lbfgsb3c"` with `fast = TRUE`, `"bobyqa"` with `fast = FALSE`, as the fetch summarised it), and `maxOuterIterations` is described as a number of L-BFGS-B iterations but is listed among the ignored parameters; which optimiser runs is version-dependent and is recorded at install time (POP-ORA-02). The method is not required to follow its path, only to reach the same optimum within the method tolerance (POP-EST-06). Exact gradients by sensitivity equations (S-58, abstract level) are a later optimisation, not a change of the objective.

**Stopping.** (1) Candidate: the predicted decrease of the BFGS step is at most ε_out. (2) Confirmation, once per candidate: the finite-difference Hessian R of the OFV at the candidate (POP-COV-02), and the Newton decrement of the OFV Δ_out = ½·gᵀR⁻¹g over the free variables; the fit has converged when Δ_out ≤ ε_out, **absolute** (the OFV can be negative, FIT-ML-08). If R is not positive definite at a candidate, the candidate is a saddle or a flat direction: the iteration continues with a steepest-descent step, and if it comes back to the same point the status is `singular`. (3) A limit of K_max accepted iterations. ε_out, K_max and h are OP-11.

**Status** (the names of FIT-ML-08): `converged`, `max_iterations`, `no_decrease`, `singular`, `non_finite`, `at_bound`, and the new `inner_failed` (every trial point in the line search had an inner problem that failed). The trace has one row per accepted iteration, including iteration 0: iteration, OFV, `ofv_convention`, φ in user units, ν, number of halvings, the decrement; the last row carries the status.
- Status: `assumed`
- Sources: design choice; S-49 (`outerOpt`, `maxOuterIterations`, `maxInnerIterations`, `nlmixr2est` 7.2.1, at the level of the argument descriptions, `documented, untested`); D (the envelope argument; truncation and noise of a central difference); FIT-ML-07, -08, FIT-BND-01 (the rules reused); S-58 (exact gradients exist, abstract level); D (the Newton decrement of a quadratic model, ½·gᵀR⁻¹g, in OFV units).

### POP-EST-04 Result, statuses of the estimates and flags
The result holds: the method, `ofv_convention`, OFV at the estimate, θ̂ (typical values), Ω̂ (variances and covariances, and the standard deviations and correlations derived from them), ξ̂ in the user's units (FIT-ML-17), the η̂_i of every subject used (NC for a subject with no observation), the counts of POP-DAT-01 (`n_subjects` and `n_observations`: N, the observations used, which is the N of the BIC, POP-DIA-04), the status, the trace, and the diagnostics of section 6, and the **covariance block** (decision taken meanwhile, 2026-11-08, reversible by Abdou, OP-04): the `sandwich`, `r` and `s` matrices (each with its own NC reasons, POP-COV-03), the kind that is printed (the option `covariance`, POP-COV-01), the standard errors of the printed kind and of the three (`se_by_kind`), and the array `flags` of the covariance. Flags (informational unless said), with the machine names `at_bound`, `omega_collapse`, `high_eta_shrinkage`, `few_subjects`, `few_observations` and `slow_convergence`: *at bound* for a parameter; *omega collapse* when a fitted ω_k is below a small fraction of its two-stage start (OP-11) at convergence, which tells the user that the data do not identify that random effect; *high η-shrinkage* (POP-DIA-03) per random effect; *few subjects* when m is not larger than the number of elements of Ω plus P_θ,free (the covariance is flagged, POP-COV-03); *few observations* when N is not larger than P_θ,free + Q plus the free elements of Ω (POP-INN-03); *slow convergence* above a number of iterations (OP-11). - Status: `assumed`
- Sources: design choice; FIT-ML-08, -15, -17, -20 (the layout and statuses carried over).

### POP-EST-05 Initial estimates: the two-stage method (card T-154)
The user's initial values, where given, are used. For the others the engine computes a **two-stage** start:

1. Stage 1: one ML fit per subject with the chosen structural model and error model, using `subject = all` (DAT-USE-02) and the initial estimates of FIT-INI-01 to 04 per subject, with the objective `ml` of FIT-ML-01. A subject whose individual fit is refused (FIT-ML-14, -15, an `unbounded_likelihood`), does not converge, or ends with a parameter on a bound is **left out of the means** and listed; it still takes part in the population fit.
2. Stage 2, over the subjects that survived (m₂ of them): θ_k⁰ = exp(mean of ln P_ik) for a parameter with a random effect (the geometric mean, the median of a log-normal); the natural-scale mean for a parameter without one; Ω⁰ = the sample covariance of the vectors (ln P_ik)_k with divisor m₂ − 1, its diagonal for `diagonal`, the full matrix for `block`; ξ⁰ = the mean over the surviving subjects of the individual error parameters, on the variance scale of FIT-ML-05.
3. A start that cannot be built is an error that says what to give: fewer than 2 surviving subjects, a diagonal element of Ω⁰ equal to 0 (all subjects returned the same value of that parameter), or, for `block`, a sample covariance that is not positive definite (then the diagonal is used for the start and a note says so).

The two-stage values are only a start: they are not a statistical estimate of Ω (the variance of individual estimates includes their own estimation error and is too large when subjects have few observations), so the fit moves away from them. The result records the start used (`start`: user, two_stage, or mixed per parameter) as FIT-ML-20 does.
- Status: `assumed`
- Sources: card T-154 (two-stage start); `specs/fit.md` DAT-USE-02 and FIT-ML-10, -01, FIT-INI-01 to 04 (the machinery); S-56, S-57 (abstract level: the nonlinear mixed-effects model whose two-stage start is the standard one); D (the geometric mean as the median of a log-normal; the inflation of the between-subject variance by the individual estimation error).

### POP-EST-06 What the method tolerance is meant to cover
Tests of estimates compare the engine with the open oracle within a **method tolerance** (`AGENTS.md` section 5 asks for the numbers through `board/QUESTIONS.md`; none is written here). What the tolerance is meant to cover, and not to cover:

- It covers: (1) two correct optimisers stopping at slightly different points of a flat objective (the stopping test measures a gain in OFV, not a distance, so the parameters can differ by far more than the OFV); (2) the accuracy of the inner solves and of the finite-difference derivatives, which differ between implementations; (3) the numerical accuracy of the reference itself (its ODE solver tolerance when it does not use a closed form: with `sigdig = 3` the page of S-49 gives atol 1e-6 and rtol 1e-3, so a reference at that setting is much less accurate than the engine, and the oracle must record the reference at two settings, POP-ORA-02); (4) the rounding of data and times between tools.
- It does not cover: a different objective formula (POP-OBJ-04, OP-02: a method difference to document), a different constant in the OFV (an explicit shift, POP-OBJ-05, never a tolerance), a different parameterisation of the same model, a different local minimum (the oracle checks the OFV at the engine's estimate under the reference and at the reference's estimate under the engine; a lower OFV on either side is a finding, not a tolerance), a different error-model form (FIT-ML-03) or a different treatment of the data (POP-DAT-02).

Separate tolerances are proposed, with the quantity each covers, in the report of this card: OFV at fixed parameters (the tightest, POP-ORA-02), OFV at the estimate, typical values, the elements of Ω, the error parameters, the standard errors, and η̂_i. A tolerance is a statement about a gap in a quantity of the output; it is never widened to make a test pass (`AGENTS.md` section 5).
- Status: `assumed`
- Sources: `AGENTS.md` section 5; FIT-OBJ-01 and the line of `AGENTS.md` section 5 on optimisers (two optimisers do not reach the same minimum bit for bit); S-49 (`sigdig` and the ODE tolerances); design choice.

## 5. The covariance of the estimates (card item 5)

### POP-COV-01 Which matrix, and how it is built
Let φ̂ be the converged vector, **R** = ∇²_φ OFV(φ̂) (the Hessian of the full OFV) and **S** = Σ_i g_i·g_iᵀ with g_i = ∇_φ OFV_i(φ̂) (the sum over subjects of the outer products of the gradients of the per-subject OFV; by independence, the empirical covariance of the scores). Three estimators of Cov(φ̂) are offered:

| `covariance` | formula | reading |
|---|---|---|
| `sandwich` (**printed by default**) | R⁻¹·S·R⁻¹ | robust to a misspecified error structure; needs R only to be invertible, and many subjects for S to be reliable |
| `r` | 2·R⁻¹ | the inverse observed information; right if the model is correct |
| `s` | 4·S⁻¹ | the inverse of the outer-product information; needs m larger than the number of parameters |

(D: OFV = −2 ln L, so the information is R/2 and the score of a subject is −g_i/2; the sandwich H⁻¹·(Σ s·sᵀ)·H⁻¹ with H = R/2 and s = g/2 is R⁻¹·S·R⁻¹, the inverse information is 2R⁻¹, and the outer-product form is 4S⁻¹.) The reference tool offers the same three, with the sandwich as its default and the same factors (S-49, `covMethod`: "r,s", "r", "s"; the page also lists other kinds, which are not used). **Why the sandwich is the default and not the expected information of FIT-ML-17:** the FOCEI objective is an approximation of the likelihood, so the model-based inverse information is not exactly the covariance of its minimiser, which is the case the sandwich is for; no closed-form expected information exists for a population model in general, so FIT-ML-17's matrix is not available (the working assumption written there for brick 3 is replaced by this rule); and the sandwich is the reference tool's default, which the oracle compares with. The price: with few subjects S is noisy or rank-deficient (the flag *few subjects*, POP-COV-03).

**Decision taken meanwhile (2026-11-08), reversible by Abdou (OP-04): the review's proposal stands. The sandwich is printed, and all three covariances are computed and returned.** The option `covariance` (`sandwich`, `r`, `s`; default `sandwich`) picks only **the kind that is printed**: the standard errors, the RSE and the correlations of the main table are those of that kind. Whatever its value, every successful fit returns the three matrices in the covariance block of POP-EST-04, each with its own NC reasons (POP-COV-03), and the standard errors of all three in `se_by_kind`. The cost is that of R and S, which the sandwich needs anyway (POP-COV-02); `r` and `s` are algebra on them. An unknown kind is `invalid_option`.
- Status: `assumed`
- Sources: S-49 (`covMethod`, `nlmixr2est` 7.2.1 (and 2.2.2 earlier), the three kinds and the sandwich default, read through a fetch excerpt); D (the factors 2, 4 and the sandwich from OFV = −2 ln L); FIT-ML-17 (the working assumption this replaces).

### POP-COV-02 How the derivatives are taken
R and the g_i are **central finite differences of the OFV**, in the unconstrained vector φ, with each evaluation re-solving the inner problems (the OFV as a function of φ alone, with η̂_i = η̂_i(φ)). The shortcut that the gradient of the sum of the h_i at the mode only needs the partial derivatives at fixed η̂_i (the envelope argument) does not extend to the second term of the OFV, which depends on η̂_i through G and σ̂; it is not used. Requirements: (1) the inner problems are solved to the polish floor of FIT-ML-08, as in every difference quotient (POP-INN-02), so that the inner error is far below the difference quotient (the value of h is OP-11); (2) g_i is the difference of the single-subject OFV_i, so S needs 2·p extra evaluations of each subject (p the length of φ) and R the p(p + 1) or 2p² evaluations of the whole OFV by second differences, or p gradients; the cost is bounded by the fit's own; (3) the step is a fraction of max(|φ_j|, 1) (OP-11); (4) the sums over subjects are in subject order (POP-DET-01). The matrix is then carried from φ to the user's scale by the **delta method**: SE of θ_k = θ_k·SE(ln θ_k) for a log-scale one; for Ω, the Jacobian of the map from the log-Cholesky vector to (Ω_kl) (closed form: Ω = L·Lᵀ, ∂Ω/∂λ by the product rule); for ξ, FIT-ML-17 (SE_a = SE_A/(2a)). A parameter on a bound, or a fixed one, is removed before the inversion and the covariance is that of the free block, conditional on the bound (FIT-BND-02). Exact derivatives of the OFV by sensitivity equations are `later` (S-58).
- Status: `assumed`
- Sources: design choice; D (the envelope argument and why the log-determinant term needs the full derivative; the delta method); FIT-ML-08 (polish), FIT-ML-17 (delta method for ξ), FIT-BND-02.

### POP-COV-03 When the covariance is "not computable" (NC)
As in FIT-ML-17, a standard error that cannot be computed is shown as NC with its reason, never as 0 or as a blank:

- `not_converged`: the status of POP-EST-03 is not `converged` (the statistics are shown with the "not converged" mark, FIT-CNV-03).
- `singular`: R is not positive definite at φ̂ (its Cholesky factorisation fails, or an eigenvalue is not positive). Then `sandwich` and `r` are NC (R is needed by both); `s` does not need R and is still returned if S has rank p. For `s` alone, `singular` also means that S is not invertible (its rank is below p). Each of the three matrices carries its own reasons (decision taken meanwhile, 2026-11-08, reversible by Abdou, OP-04: all three are returned, POP-COV-01).
- `at_bound`: the parameter is held on a bound or fixed; its SE is NC with that reason and the others are conditional (POP-EST-02).
- `non_finite`: a difference quotient needed an OFV that was not finite or an inner problem that failed (`inner_failed` at a differenced point).
- `few_subjects` (a flag on the sandwich, not an NC): m is not larger than p; S then has rank at most m and the sandwich is a poor estimate in the directions S does not span. The numbers are shown with the flag; `s` is NC. The flag `few_observations` of POP-INN-03 is carried in the same array `flags`.
There is no automatic fallback from one kind to another: the printed kind (POP-COV-01) is never replaced by another kind. If it is NC, the main table shows NC with its reason, and the other two kinds are still in the covariance block for the user to read.
- Status: `assumed`
- Sources: FIT-ML-17 (reasons), FIT-CNV-03, FIT-BND-02; design choice.

### POP-COV-04 SE, RSE and correlations
**Decision taken meanwhile (2026-11-08), reversible by Abdou (OP-04): the SE, RSE and correlations are those of the printed kind, `sandwich` by default (POP-COV-01).** SE_j = √Cov_jj in the user's units (POP-COV-02), of the printed kind (POP-COV-01); `se_by_kind` holds the same for the three kinds (NC where a kind is NC); RSE_j = 100·SE_j/|estimate_j|, NC at an estimate of 0; the correlation matrix is that of the covariance in the user's units over all free estimates (θ, the elements of Ω, ξ), with its eigenvalues and condition number as in FIT-OUT-05. For Ω the estimates reported are the variances and covariances; the standard deviations and correlations of the random effects are derived values with their own delta-method standard errors; the standard error of a variance is not a symmetric interval for it (a variance is positive), and no confidence interval is defined in v1 (the choice between a normal and a Student quantile is open, as OF-21 for the individual fit).
- Status: `assumed`

## 6. The diagnostics (card item 6)

### POP-DIA-01 PRED, IPRED, IWRES
For every observation used, at the estimate: **PRED_ij = ŷ_ij(0)**, the population prediction, which is the prediction of the typical individual, the **median** of the individual predictions for a monotone dependence on a single random effect (POP-MOD-01), not their mean; **IPRED_ij = ŷ_ij(η̂_i)**; **IWRES_ij = (y_ij − IPRED_ij)/σ̂_ij** with σ̂_ij = g(IPRED_ij; ξ̂), which is FIT-ML-18 applied to the individual prediction. The summaries of FIT-ML-18 (mean, standard deviation with divisor N − 1, counts of |IWRES| > 2 and > 3) are computed over all subjects. The fit does not impose Σ IWRES² = N (FIT-ML-13 is a property of the individual fit: the population fit's optimum includes the prior terms), so the standard deviation of IWRES is an honest diagnostic here. Rows left out (missing, BLQ) have none, and a subject with no used observation has none.
- Status: `assumed` for the names and the summaries; `documented, untested` for IWRES (S-53)
- Sources: FIT-ML-18; S-53 (IWRES as the individual weighted residual, abstract and Methods prose); D (the median).

### POP-DIA-02 CWRES
The conditional weighted residual of subject i is built from the linearised mean and covariance of POP-OBJ-02 at η̂_i (for `foce`, with the σ⁰ of POP-OBJ-06 in C_i): E_i, the S-52 expectation f(θ, η̂) − (∂f/∂η)·η̂, and C_i, the covariance (∂f/∂η)Ω(∂f/∂η)ᵀ + the error term. **Decision taken meanwhile (2026-11-08), reversible by Abdou (OP-06): the review's proposal stands, and the default CWRES is the Cholesky form, in the time order of DAT-ORD-01, with the diagonal form as a second column.**

- **`cwres`, the default, answer name `cwres_cholesky`:** w_i = L_i⁻¹·(y_i − E_i), with C_i = L_i·L_iᵀ and L_i lower triangular (the Cholesky factor that the objective already computes, POP-OBJ-02). The order of the observations in y_i is the order of the subject's rows after DAT-ORD-01 (non-decreasing time, DAT-ORD-01), with the rows left out (missing, BLQ, before the dose) removed; two observations at the same time cannot occur (`duplicate_times`, DAT-ORD-01). The form depends on this order, and so Σ_j w_ij² equals the squared-distance term of OFV_i (PX3).
- **`cwres_diagonal`, the second column:** (y_ij − E_ij)/√(C_i,jj), each residual by its own marginal standard deviation; it does not depend on the order of the observations.
- **The symmetric root** (C_i^(−1/2) from the eigen-decomposition, which also has Σ w² equal to the distance term and does not depend on the order) is **not returned by the engine in v1**; the oracle keeps it as a cross-check (PX3: on subject 1 it gives 0.65038, 1.13244, 0.59827, −0.13426, −2.07139, 0.61932, checked by the reader against the reviewer's values).

Three points differ from the slides' text and are decisions of this rule. (1) The slides evaluate the error derivative at ε = 0 without saying at which η; here it is at η̂_i, consistent with the interaction of POP-ERR-01 (for `foce`, the error variances are the σ⁰ of POP-OBJ-06 and there is no interaction). (2) The slides write the residual as a vector multiplied by an inverse square root of the covariance matrix of that vector, and do not say which square root; the Cholesky form above is **this spec's default, not the S-52 definition**. The three roots differ materially (PX3). Which one a reference tool reports is open item OP-06, still to be measured by the oracle. (3) IWRES (POP-DIA-01) is unchanged by the method: it uses g(IPRED), the individual prediction, after `foce` as after `foce_i`. CWRES is not defined after an FO fit (POP-OBJ-03). A bias in the CWRES with respect to the fitted FOCE is a known behaviour that the cited slides discuss; the erratum of S-54 corrects the printed residual of that paper to y − E(y), consistent with the definition here.
- Status: `documented, untested` for the form of CWRES; `assumed` for the interaction extension, the Cholesky default and the second column
- Sources: S-52 (the CWRES definition; slides, equations garbled in the text extraction and read together with the layout); S-54 (the erratum, residual y − E(y), at the level of a note); D (the interaction extension; the identity Σ w² = squared-distance term); H34 (R: PX3).

### POP-DIA-03 η-shrinkage and ε-shrinkage
For random effect k, over the subjects used with a defined η̂ (m₁ of them): **η-shrinkage_k = 1 − SD(η̂_k)/ω̂_k**, SD the standard deviation over subjects of η̂_ik (divisor m₁ − 1, OP-10) and ω̂_k = √Ω̂_kk the estimate. **ε-shrinkage = 1 − SD(IWRES)**, SD over all observations used (divisor N − 1, FIT-ML-18). **Decision taken meanwhile (2026-11-08), reversible by Abdou (OP-10): the divisors m₁ − 1 and N − 1 stand, as proposed.** Both are the definitions of the cited paper at the level of its abstract and Methods prose: the typeset equations (Eqs. 3 to 5) were not readable, so the SD's divisor and the exact set of observations are the reader's reading. 0 means no shrinkage and 1 means complete; a negative value is possible and is shown as it is, because the paper says it can signal misspecification. NC when m₁ < 2, when ω̂_k = 0, or after an FO fit. A high η-shrinkage makes the EBE-based diagnostics (η̂ plots, IPRED, individual covariate relations) uninformative; the flag *high η-shrinkage* is raised at a threshold that is OP-11 (the paper discusses ranges, not a rule read in full).
- Status: `documented, untested`. **Nobody on this project has read the typeset equations of Savic and Karlsson (Eqs. 3 to 5 are images)**; the definitions are those of the abstract and the Methods prose, and the divisor and the set of observations are open (OP-10).
- Sources: S-53 (Savic and Karlsson 2009: the abstract's 1 − SD(η_EBE)/ω and 1 − SD(IWRES), the Methods prose on direction and sign; equations 3 to 5 are images, not read); FIT-ML-18 (SD of IWRES); H34 (R: PX3).

### POP-DIA-04 AIC and BIC, and the parameter count
AIC = OFV + 2·k and BIC = OFV + k·ln N, with OFV of the convention stated (`ofv_convention` is returned with them, POP-OBJ-05) and **k the number of free parameters estimated**: the free typical values P_θ,free, plus the free elements of Ω (q for `diagonal`, q(q + 1)/2 for `block`, less those fixed), plus Q (the error parameters, **including a component that ended on its bound**, FIT-ML-16). Fixed parameters are not counted. N is the number of observations used (**decision taken meanwhile, 2026-11-08, reversible by Abdou, OP-05**: N = observations, as proposed; using the number of subjects instead is not offered). Every answer that carries a BIC carries `n_observations` next to it, and `k`, so that the value can be recomputed and compared. The rule of FIT-ML-16 on comparisons holds: only for the same observations, the same conventions, and models fitted by the same method (an FO fit and a FOCEI fit have different objectives; comparing their OFV is meaningless and is refused by any comparing command). AIC and BIC are NC when the OFV is not finite or the fit did not converge (shown with the mark).
- Status: `assumed`
- Sources: FIT-ML-16 (S-27, S-29: the form −2 log-likelihood plus a penalty); design choice for the count and for N; D.

## 7. The data (card item 7)

### POP-DAT-01 The input: the population dataset
The input is the dataset of `specs/data.md` (the event layout, DAT-LAY-01, with several subjects, or a profile-layout file with several subjects read as in DAT-LEG-01), with the same reading of a subject as the individual fit of DAT-USE-02: **one dose row per subject in v1**, giving its dose, dose time and, for an infusion, duration or rate; a subject with more than one dose row is refused (multiple dosing in the population fit is `later`, OP-09: **decision taken meanwhile, 2026-11-08, reversible by Abdou**, one dose per subject in v1, as proposed), with the code `unsupported_history` and the sentence of POP-INN-03 item 7 (DAT-USE-02 gives no sentence for a population run, only "more than one dose row is refused for that subject"). ### POP-DAT-02 BLQ: exclusion only in v1, the censored likelihood is an open item

The method that keeps them, a likelihood term for the probability of being below the limit given η (M3, Beal 2001, S-46), changes the objective and the inner problem (the term is not Gaussian) and is **not specified**: it is open item OP-07 (**decision taken meanwhile, 2026-11-08, reversible by Abdou**: M1 in v1, M3 `later`, as proposed). No formula for it is given here. The data columns that would carry the censoring flag and the limit are already in `specs/data.md` (DAT-CEN-02), so the dataset does not change when M3 arrives.

## 8. Determinism (card item 8)

### POP-DET-01 The order of every reduction
A population fit adds numbers from many subjects, and floating-point addition is not associative: a different order is a different last digit, and a different last digit changes a convergence test and so the path of the optimiser. The rule: **every reduction over subjects, observations or parameters is a plain left-to-right sum in a fixed order that does not depend on the number of threads or on the target.** Explicitly:
1. OFV = Σ_i OFV_i is a left-to-right sum over subjects in dataset order (POP-DAT-01), as is Σ over subjects of any statistic (S = Σ g_i·g_iᵀ entry by entry, the counts, the sums for the shrinkage).
2. Within a subject, sums over observations (the stacked system, ℓ_i, the distance term) are left to right in time order of the dataset after DAT-ORD-01.
3. The standard deviation of a sample (shrinkage, IWRES summaries) is computed in two passes, in the order of the data: first the mean by a left-to-right sum, then the sum of squared deviations.
4. The linear algebra (Householder QR, Cholesky, triangular solves) is the crate's own code with a fixed loop order; no external numerical library whose summation order depends on the machine.
5. The finite-difference derivatives of POP-COV-02 sum per-subject differences in subject order too.
No pairwise or blocked summation whose block size depends on the thread count is allowed; a fixed tree that is the same for any thread count (for instance by subject index) would also satisfy the rule but costs nothing to avoid, so the left-to-right sum is the rule. Reason: the digest of POP-DET-03 must be identical, bit for bit, for 1 thread, N threads and WebAssembly.
- Status: `assumed`
- Sources: `AGENTS.md` rule 10 (same numbers on every machine; sums, products and quotients are rounded alike everywhere); D (non-associativity of floating-point addition).

### POP-DET-02 Each subject is a pure function; threads sit outside the library
Layers L0 to L3, which hold the population fit, compile for WebAssembly and contain no threads (`AGENTS.md` golden rule 9); a parallel evaluation over subjects, if any, is arranged by the caller in `apps/`. The contract that makes this safe: **the inner problem and the per-subject quantities (η̂_i, OFV_i, g_i, the diagnostics) are a pure function of the data of subject i, of (θ, Ω, ξ) and of the warm start of subject i** (POP-INN-02), where the warm start is **the η̂_i of the last accepted outer iterate of that subject and nothing else** (every evaluation, including the 2p points of a difference quotient, starts from it; a point evaluated for a difference never becomes the start of another), never a value of another subject or one that depends on the order in which threads finished. The library exposes the per-subject evaluation and the reduction separately: the caller (any number of threads) fills an array indexed by subject, and the library then reduces it in index order (POP-DET-01). A partial sum per thread added at the end is forbidden, because its grouping depends on the thread count. No global state, no shared random number, no clock.
- Status: `assumed`
- Sources: `AGENTS.md` rules 9 and 10; design choice.

### POP-DET-03 The same digest on 1 thread, on N threads and in WebAssembly
**Caladrius's rule, with its reason:** the answer of a population fit is the same, bit for bit, whatever the number of threads and the target; and a test proves it. Reason: a user who reruns the same project on a laptop, in the browser and in a cloud session must be able to rely on the seal (`AGENTS.md` rule 10, `project.replay`), and a population fit is the first command whose result could depend on how the work was split. The population workload is added to the fixed workload of `cargo xtask digest`: a small dataset (the examples PX1 and PX2 are candidates), FOCEI and FO, the full result in canonical text (OFV and its convention, φ̂, Ω̂, ξ̂, every η̂_i, SE, the diagnostics, the number of iterations and the trace), hashed with SHA-256. CI compares the digest on Linux, Windows, macOS and in WebAssembly under Node, and a threaded test compares 1 thread against N for at least one N that does not divide the number of subjects and one N larger than the number of subjects. Because the trace is in the digest, the **path** of the optimiser must be identical, not only its end point. The `libm` functions replace the platform's `exp`, `ln`, `powf` (`AGENTS.md` rule 10).
- Status: `assumed`
- Sources: `AGENTS.md` rule 10 (the digest and the seals); design choice with the reason above.

### POP-DET-04 No randomness in the fit
The population fit uses no random number: the start is deterministic (POP-EST-05) and the optimiser is deterministic. Any later command that simulates (population simulation is the next item of `AGENTS.md` section 1) draws from a stream seeded by a parameter, with a generator written in the engine and specified in `specs/` (`AGENTS.md` rule 10); it is not specified here. The sealed datasets of POP-ORA-04 are simulated in R, with R's generator, and committed as data; the engine never has to reproduce R's stream.
- Status: `assumed`
- Sources: `AGENTS.md` rule 10 (no random number except a stream drawn from a seed that is a parameter).

## 9. What the oracle can test, in order (card item 9)

### POP-ORA-01 (a) Cases where the objective is exact, at 256 bits, with no population software
**Cases.** A model linear in η with an additive error: ŷ_ij(η) = a_ij(θ) + z_ij(θ)ᵀ·η (the identity-link test model of POP-MOD-05), σ = a constant, η ~ N(0, Ω). Then y_i is exactly Gaussian, y_i ~ N(a_i, Z_i·Ω·Z_iᵀ + σ²·I), and

OFV_i = n_i·ln(2π) + ln|C_i| + (y_i − a_i)ᵀ·C_i⁻¹·(y_i − a_i),  C_i = Z_i·Ω·Z_iᵀ + σ²·I,

is the exact −2 ln L_i. Both POP-OBJ-02 and POP-OBJ-03 and the three Laplace forms of POP-OBJ-04 equal it (D: the linearisation is exact, the Hessian of ℓ_i is constant and equal to 2ZᵀZ/σ², and the mode is the posterior mean). **This is the first oracle because it needs no population software, only the formula and 256-bit arithmetic.**

**How it is computed.** In R with `Rmpfr` at 256 bits, **with every input parsed from its decimal string** (`mpfr("2.1", 256)`, not a double converted to 256 bits: the data are decimal numbers and a double is not 2.1), π from `Const("pi", 256)`, the determinant and the quadratic form written out with the explicit Cholesky factor or closed forms for the balanced designs (in the reader's try, `solve` and `det` on `Rmpfr` matrices did not return in a reasonable time for a 4 × 4 case, so the script should carry its own small Cholesky). Rounded once to double for the file. The oracle also provides: the exact maximum-likelihood estimates of (θ, Ω, σ²) by maximising this closed form at high precision (the engine's estimate at the ML optimum is an estimate that needs no reference tool), the exact observed information at that point (the Hessian of the closed form), and the η̂_i in closed form (posterior means, example PX1). Cases to include: one random effect (an intercept) and two (an intercept and a slope) with a diagonal Ω and with a full block; balanced and unbalanced designs (different n_i and times per subject); a subject with a single observation; m = 2; Ω with a small variance (near the collapse of POP-EST-04) and with a large one; σ small and large relative to the random effects.

**What it tests.** The value of OFV at fixed parameters to rounding (the tolerance here covers only rounding and the order of the sums, not a method), the η̂_i, the covariance (R of POP-COV-01 against the closed-form Hessian), and the estimates (ML optimum of the closed form against the engine's, within the stopping tolerance of the engine). Because FO = FOCEI = the exact value in these cases, a mismatch here is a bug and cannot be a method difference.

**A second family, an exact identity but not an exact marginal (added after review, H35).** A model **nonlinear** in η with an **additive** error (σ constant, or frozen so that ∂σ/∂η = 0): the exact marginal is not available in closed form, but the three candidates `linearised`, `laplace_expected` and `laplace_no_variance` are equal to rounding (the identity of POP-OBJ-04), while `laplace_full`, FO and the exact marginal differ from them. The test is the equality of the three to rounding (to 256-bit rounding in the script, to the rounding of the order of the sums in double precision), and that `laplace_full` differs by the amount the script gives (example PX5); it is not a test against the exact marginal. With interaction (proportional or combined error) the three split, so this family cannot identify the interaction.

**A third family: σ frozen (updated by T-166, 2026-11-08).** The oracle's `frz_*` cases hold σ fixed while the mode is found, with a proportional or combined error, so the identity of POP-OBJ-04 applies to them. There are two forms, and they are not the same function (H36, PX6): (i) **σ frozen at the population prediction ŷ(0)** (`frz_*_pred0`): this is the objective of the engine's method `foce` (POP-OBJ-06), so these cases are **engine cases**: the engine run with `method = foce` must reproduce the stored `linearised` value of each subject and the total to rounding, and the `laplace_no_variance` and `laplace_expected` values equal it by the identity; (ii) **σ frozen at its value at the mode**, found by a fixed-point iteration (`frz_*_mode`): not an engine method, so these cases stay **testkit-only identity checks** of POP-OBJ-04. The set `POP_EXACT_IDENTITY_CASES` of the testkit, which holds both, is split accordingly in the oracle's next round.

**A fourth family: exact estimates for the balanced linear case (added by T-166 on 2026-11-08, for card T-168; H38).** The three families above fix the parameters and ask for the objective. This one asks for the **estimates**, which no reference tool is needed for. Take `identity_linear` (POP-MOD-05) with an `additive` error: the model is linear in η and σ does not depend on η, so FOCEI (and FO, and FOCE) is the exact marginal likelihood of a linear mixed model, y_i ~ N(a_i, Z_i·Ω·Z_iᵀ + σ²·I). When **every subject has the same times** (a balanced design) and every column of Z lies in the column space of the fixed-part design [1, t] (so `z_powers` of `[0]` or `[0, 1]`, not `[0, 1, 2]`), the generalised least squares estimate of (θ_1, θ_2) is the ordinary least squares fit of the pooled data, whatever (Ω, σ²), and the maximum (θ̂, Ω̂, σ̂², and the OFV there) is known in closed form (q = 1, and a block Ω for q = 2) or by a low-dimensional search.
- **q = 1** (a random intercept; m subjects, n common times, N = m·n). Let r_ij be the residuals of the pooled OLS fit, r̄_i their mean in subject i, W = Σ_ij (r_ij − r̄_i)² and B = n·Σ_i r̄_i². Then σ̂² = W/(m(n − 1)), λ̂ = B/m for λ = σ² + n·ω (ω is a variance), and ω̂ = (λ̂ − σ̂²)/n if λ̂ > σ̂²; **this closed form holds only when λ̂ > σ̂² (that is, ω̂ > 0); the other case is the boundary case**, where the maximum is on the boundary: ω̂ = 0 and σ̂² = (W + B)/N. At an interior maximum OFV = N·ln 2π + m(n − 1)·ln σ̂² + m·ln λ̂ + N (convention `full`; drop N·ln 2π for `no_2pi`, POP-OBJ-05).
- **q = 2, block Ω** (derived by the reader, D; not run, so `assumed`). Split each residual vector r_i into its projection on the columns of Z, b_i = (ZᵀZ)⁻¹Zᵀr_i, which is N(0, Ω + σ²(ZᵀZ)⁻¹), and the orthogonal part (I − P_Z)r_i, which is N(0, σ²) in n − q dimensions, independent of b_i. With S = (1/m)·Σ b_ib_iᵀ and W' = Σ_i ‖(I − P_Z)r_i‖², the objective separates and the maximum is σ̂² = W'/(m(n − q)) and Ω̂ = S − σ̂²(ZᵀZ)⁻¹ when that matrix is positive definite (n > q is needed); the maximum is then OFV = N·ln 2π + m·ln|ZᵀZ| + m·ln|S| + m·q + m(n − q)·ln σ̂² + m(n − q). If that Ω̂ is not positive definite the maximum is on the boundary and has no closed form.
- **q = 2, diagonal Ω.** Ω + σ²(ZᵀZ)⁻¹ is not diagonal unless ZᵀZ is, so the constrained maximum has no closed form in general: it is a search over (ω_1, ω_2, σ²) on the profile above, and only the references (2) and (3) below apply to it.
- **A design whose maximum is on the boundary**: the q = 1 case with λ̂ ≤ σ̂² (the sum of squares between subjects is small), where ω̂ = 0 and the engine must report `at_bound` or the collapse of POP-EST-04. A boundary of the q = 2 problem has no closed form and is given by (2) and (3) only.

**References, three, independent of each other**: (1) the closed form at 256 bits with every input parsed from its decimal string (the method of the first family), (2) `nlme::lme(method = "ML")` in R (a fit of the same likelihood by another method: `random = ~ 1 | id`, `pdDiag` or `pdSymm` for q = 2), and (3) a direct maximisation, in double precision, of the objective of POP-OBJ-02 (exact in this case), from several starts. A disagreement among the three is a bug in a reference and not a method difference. **What it tests:** the outer optimiser and the covariance end to end on a problem whose answer is known to many digits, with the engine's estimate checked against the closed form at the tolerance of the stopping rule of POP-EST-03 and not at a tolerance borrowed from a tool. **Hand check H38 (R, one case):** m = 6 subjects, the times 0.5, 1, 2, 4 and 8 for each (N = 30), `z_powers = [0]`; the data are generated with `set.seed(38001, kind = "Mersenne-Twister", normal.kind = "Inversion", sample.kind = "Rejection")` and, for each subject in order, first `b_i = rnorm(1, 0, 2)` and then the five errors `rnorm(5, 0, 0.9)`, y = 10 + b_i − 0.8·t + error at the five times, rounded to three decimals (ω is a variance: the draw has ω = 4, standard deviation 2; σ = 0.9 is a standard deviation); the 30 rounded values are tabulated in H38 of `specs/sources.md` section 15, so that nothing depends on the generator; the closed form at 256 bits and `nlme::lme` ML agree to 4.9e-15 on θ_1, 6.5e-17 on θ_2 and to 3.3e-8 on ω and 2.1e-8 on σ² (the variance components were read through `VarCorr`, which prints 8 digits, so this is the rounding of that print and not a difference of estimates); the direct maximisation agrees on the OFV to 8.9e-15 and on the parameters to 1.2e-7 (the objective is flat near its optimum). **The constant convention of the comparison is `full`**: `-2·logLik` of `lme` equals the closed-form OFV with the N·ln 2π term to 8.9e-15 and differs from the `no_2pi` value by 55.136 = N·ln 2π, so the comparison is made in the `full` convention (OP-03). The values are in `specs/sources.md` section 15 (H38). The cases themselves are not yet files of the oracle: they are the proposal for card T-168.
- Status: `assumed` (the fourth family is `assumed` too: one case is checked by H38, the q = 2 formulas are not run) (becomes `confirmed by oracle` when T-152 produces the files); example PX1 gives the values for one case. The files now exist (`oracle/expected/pop/exact/`) and the testkit reproduces them with independent code; the grade stays until a versioned engine test does
- Sources: D (the Gaussian marginal of a linear model; the Hessian and the mode); H31 (R: `Rmpfr`, 256 bits: the closed form and the Laplace form agree to 256-bit rounding, example PX1); H35 (the nonlinear additive identity, example PX5); H38 (R: the balanced q = 1 case, the closed form at 256 bits against `nlme` ML and a direct maximisation); `AGENTS.md` section 5 (independent computation).

### POP-ORA-02 (b) OFV at fixed parameters against the open reference tool
**How the reference evaluates the objective without estimating** (from its own documentation, S-50 and S-49; version read: `nlmixr2est` 7.2.1, to be recorded again at install time). **The documented route** is the `posthoc` method: its control page says that `maxOuterIterations` is ignored and always set to 0, so the fit is the conditional modes at the given initial values and the objective at them; but its `interaction` default is FALSE, so **the oracle must pass `interaction = TRUE`** or it obtains FOCE, not FOCEI. A second route, `est = "focei"` with `control = foceiControl(maxOuterIterations = 0, covMethod = "")`, comes from the examples in the help of `foceiFit` of the older `nlmixr` package; the `foceiControl` page lists `maxOuterIterations` ("maximum number of L-BFGS-B optimization for outer problem", default 5000) under a heading of ignored parameters and does not say what 0 does there, so that this route returns the objective at the initial values is **an inference, `documented, untested`** until the tool is installed. FO is requested with the flag `fo = TRUE`, and the interaction is the flag `interaction` (TRUE is FOCEI, FALSE is FOCE; its default is TRUE in `foceiControl` and FALSE in `posthocControl`; S-49). The random effects at their conditional modes are found by the inner problem; a way to evaluate at given η is the argument `etaMat` ("initial (or final) ETA estimates, can also be a prior fit") together with `maxInnerIterations = 0` (an inference as well).

**What to record per case.** The reference's objective value (OBJF, from which the constant is omitted) **and** its −2·logLik with `adjLik = TRUE` (the signature default of `foceiControl` is TRUE: "adjusts the likelihood by the 2π constant the objective otherwise omits"; the objective value itself is not adjusted), the version of `nlmixr2`, `nlmixr2est` and `rxode2`, **the value of the argument `foce` of `foceiControl` (`"nonmem"` or `"foce+"`, an argument value of the open tool; versions up to 6.0.1 behave like `"foce+"`, the argument exists from a later version and the NEWS entry is that of 7.2.0, the versions in between were not read: S-80, S-81, so the tool version must be recorded) and the value of `interaction`, because they change the objective for a proportional or combined error (POP-OBJ-06) and a run without them cannot be compared**, the value of `sigdig` or `atol`/`rtol`, and, to bound the reference's own numerical noise, the OFV at two values of those settings. The reference solves ODEs by default; a **closed-form linear compartment model** in the reference (the `linCmt()` facility of `rxode2`, not read) removes the ODE error and should be used where available; if only an ODE solution is possible, the case is tolerant only to the reference's accuracy (POP-EST-06). The OFV is compared with `ofv_convention` made explicit: **the test is that the difference −2·logLik (adjLik = TRUE) minus OBJF equals N·ln(2π)** for each case (N the number of observations); if it does not, or if it differs by a per-subject term, the case is a method difference, not a tolerance. This does not close OP-03, which asks which convention the engine prints by default. Two further reference functions are documented without a formula: `addCwres()` (argument `focei`: "if the focei objective function is added; if not the foce objective function") and `ofv()` (types `focei`, `fo`, `foce`, `laplace#`, `gauss#.#`). What either computes is `documented, untested` at that version, and neither is used as an oracle for the formula.

**What the OFV at fixed parameters decides.** Because it involves no optimiser, it identifies the objective formula: the oracle computes the reference's number and the four candidates of POP-OBJ-02 and POP-OBJ-04 (`linearised`, `laplace_expected`, `laplace_no_variance`, `laplace_full`) for the same parameters, using additive, proportional and combined error (the variance-derivative term only matters for the latter two). **For additive error the three candidates `linearised`, `laplace_expected` and `laplace_no_variance` are the same number for any model, linear in η or not** (the identity of POP-OBJ-04, H35); only `laplace_full` and FO differ. So an additive-error case can tell `laplace_full` from the other three but cannot tell the other three apart, and **identifying the formula needs proportional or combined error**, where the three split. The same reasoning is why plain FOCE (no interaction) is a useful first case (OP-14). The case set should span: a mild and a strong nonlinearity in η, small and large Ω, few and many observations, a lag model (the kink), and FO. The agreement of the engine with the reference at fixed parameters is a far tighter test than agreement of estimates: it is the first to run once nlmixr2 is installed (Q-021). If none of the four candidates matches, the formula is a method difference to document in `specs/differences.md` and the card is reopened.
- Status: `documented, untested` (the `posthoc` route is documented; the `foceiControl(maxOuterIterations = 0)` route, `addCwres` and `ofv` are not documented as to formula or effect; the tool is not installed: Q-021)

### POP-ORA-03 (c) Estimates against the reference, with two second looks
The estimates of θ, Ω and ξ (and the OFV at the estimate, the standard errors and the η̂_i) are compared with the reference's FOCEI fit of the same data, started from the same initial values, within the method tolerance of POP-EST-06. Two second looks, which are not expected to reproduce the FOCEI estimates exactly and are used to catch gross errors and to show the spread between methods: `saemix` (stochastic approximation EM, a different estimator; its estimates differ from FOCEI by the difference of the two approximations of the likelihood and by the random stream, so its tolerance is the widest and its use is to confirm the region of the optimum, not to fix a digit), and `nlme` (the Lindstrom-Bates algorithm with `method = "ML"`: its random effects are additive on the parameter, so the log-normal structure is obtained by writing the model on the log scale, `exp(lCL)`, and the fixed effects it reports are ln θ; S-48; the variance structure of the error is `varPower`/`varConstProp` with the scale fixed or estimated as the help pages of S-39 describe). All three are open-source tools allowed by `AGENTS.md` rule 1 and section 5. `nlme` is installed (3.1.168); `nlmixr2` and `saemix` are not (Q-021). A discrepancy between the engine and the reference that is explained by the OFV-at-fixed-parameters (POP-ORA-02) is a method difference; a difference that is not is a bug or a different local minimum, and the OFV of each estimate under the other's objective separates them.

### POP-ORA-04 (d) Sealed simulate-then-fit tests
**Caladrius's rule, with its reason.** Data are simulated in R from known parameters with a recorded seed, **hashed, and committed before any engine code for the population fit exists**; a test then fits them and checks that the parameters are recovered. Reason: a test whose data are generated after the engine's output has been seen can be adjusted, even without intent, until it passes; fixing the data first, with a hash that anyone can recompute, makes the test a prediction that the engine can fail, and the order of commits is the proof. Contents of a sealed case, in `oracle/expected/pop/`:
1. The R script that simulates (model, true θ, Ω, ξ, the design, the number of subjects), the seed, and the generator settings recorded in the case file: `RNGkind()` (in R 4.5.2 it returns `"Mersenne-Twister"`, `"Inversion"`, `"Rejection"`, H34) and `R.version.string`.
2. The dataset as a file with a fixed format: the numbers written with a fixed number of significant digits chosen once (so every tool reads the same numbers, which are the data), LF line endings, UTF-8 without a byte order mark.
3. The SHA-256 of the dataset's bytes, in its own committed file, and the true parameters in the options file.
4. The ordering rule: a case is sealed **with respect to the engine commits that follow it**: the commit that adds items 1 to 3 precedes, in the history of the branch, every commit that adds or changes the engine code of the population fit that the case is used to test (a reviewer checks it with `git log`). A case added after engine code exists is allowed, but its case file says so ("added after engine commit <hash>"), and it counts as a regression case, not as a prediction. Once committed, a sealed case is **never edited or re-rolled**: a new seed is a new case, and a case on which the engine fails stays in the suite with its failure recorded.
5. The test recomputes the hash of the file before using it and fails if it differs.

**What is checked.** Two checks, which answer different questions. (i) *Agreement with the reference on the same sealed data* (POP-ORA-03), within the method tolerance. (ii) *Recovery of the truth*: the fit on a finite sample differs from the true parameters by sampling error, which a fixed tolerance on the parameters cannot describe; the quantity |estimate − true| / SE (SE from POP-COV-01 for the kind stated) is **recorded for each parameter of each replicate, not asserted**: a per-replicate bound of the form |estimate − true| ≤ c·SE fails at its nominal rate by construction, so it cannot be a pass/fail test. Only the aggregates over a set of K sealed replicates of the same design can be pass/fail: the mean of the estimates is within a small multiple of its standard error of the truth (no systematic bias), and the interval estimate ± c·SE covers the truth at about the expected rate (a coverage rate, compared with its own binomial uncertainty at K). The design numbers (K, the number of subjects and observations, c) were open item OP-13; the oracle now holds two sealed designs (`oracle/expected/pop/sealed/accurate.json` and `limits.json`, K = 200 replicates each, seeds from 15200000 and 15300000, data written to 4 significant digits). Both designs of the model class are covered: a case where FOCEI is accurate (many observations per subject, small Ω) and a case where it is known to be biased or to struggle (sparse data, large Ω), so that the suite also records the limits of the method.

**Decision taken meanwhile (2026-11-08), reversible by Abdou (OP-13): design A is asserted, design B is recorded only until T-153 has measured it.**
- **Design A, `accurate`** (`pk1.oral_1`, dose 100, `combined` error, true θ: v = 50, cl = 5, ka = 1.5; random effects on cl, v and ka with a diagonal Ω of 0.09, 0.04 and 0.16; ξ: a = 0.02, b = 0.1): 40 subjects at 8 times (0.25, 0.5, 1, 2, 4, 6, 8 and 12), 320 observations per replicate. **The aggregate checks are asserted on the typical values (θ)** and **recorded, not asserted, for Ω and ξ**. The constants in the file: c_bias 3, c_interval 1.96, c_coverage 3, nominal coverage 0.95. The bias check is |mean over replicates of the estimate − truth| ≤ c_bias·sd(estimates)/√K for each typical value, and the coverage check is that the share of replicates with the truth inside estimate ± c_interval·SE is within c_coverage·√(0.95·0.05/K) of 0.95 (`se` is that of the printed kind, POP-COV-01). A replicate whose fit did not converge is counted and reported, and left out of the aggregates; per-replicate deviations are recorded, never asserted.
- **Design B, `limits`** (the same model and dose; random effects on cl and v with a diagonal Ω of 0.36 and 0.25; ξ: a = 0.02, b = 0.15): 30 subjects at 3 times (0.5, 1.5 and 4), 90 observations per replicate. **Every aggregate is recorded and none is asserted** (`asserted` is false in the file). Its purpose is to show the limits of the method on sparse data with large Ω.
- **Promotion of B** to an asserted design, or any change to the constants or to the sealed data, is Abdou's decision (Q-026) and needs the numbers T-153 measured; the file is never edited (rule 4 above).
- **Review rule.** If the engine fails a check of design A on the bias, the failure is triaged first as a possible method difference with its numbers (for example a difference of the objective from the reference, POP-ORA-02), and it **never leads to a retune of the constants or of the sealed data**.
- Status: `assumed`
- Sources: design choice with the reason above; S-52 (the discussion, in the cited slides, of simulate-and-estimate with a known truth, at the level of the slide titles); D (the sampling-error argument); `AGENTS.md` section 5.

## 12. The vocabulary of request and answer (T-152 question 13, T-166)

### POP-API-01 The request and the answer, as the oracle adapter assumes them
**Decision taken meanwhile (2026-11-08), reversible by Abdou: the vocabulary in the header of `crates/caladrius-fit/tests/oracle_pop.rs` is adopted**, with the additions and differences below. The request is data (golden rule 4) and the same JSON as the refusal rows of `oracle/expected/pop/errors.json`, so a refusal row is given to the engine unchanged.

*Adopted as written there.* The request holds `model` (`pk1.*`, `pk2.*` ids, and `identity_linear` of POP-MOD-05), `initial` (a map from parameter to typical value; the start of a fit), `random_effects` (in the order of the rows of Ω), `omega` and `omega_shape` (`diagonal` or `block`), `error_model`, `error_init` (an array `[a]`, `[b]` or `[a, b]`, in the user's units as FIT-ML-21), `model_options.z_powers` (POP-MOD-05), `options` and `subjects` (a list of `id`, `dose`, `time` and `y`; the time axis is measured from the dose, POP-DAT-01). The answer holds `method`, `ofv_convention`, `ofv`, `subjects` (each with `id`, `ofv`, `eta_hat`, `pred`, `ipred`, `iwres` and the CWRES columns), `eta_shrinkage` (divisor m₁ − 1), `eps_shrinkage` (divisor N − 1), `k`, `aic`, `bic` (BIC with ln N), and for a fit `estimate`, `se` and `status`. A refusal is a `PopError` with `code` and `message`.

*What differs from the header, or is added.*
1. `options.method` has three values: `foce_i` (default), `foce` and `fo` (POP-OBJ-06). The header lists two.
2. The answer gains `n_observations` and `n_subjects` (POP-EST-04, POP-DIA-04).
3. CWRES: `cwres_cholesky` (the default CWRES, POP-DIA-02) and `cwres_diagonal` are returned; `cwres_symmetric` is **no longer required of the engine** (OP-06 is decided; the oracle keeps it as a cross-check). The header says all three are required while OP-06 is open.
4. Covariance: `options.covariance` (`sandwich`, `r`, `s`) picks the **printed** kind; `se` is the standard errors of that kind; `se_by_kind` and a `covariance` block carry all three kinds with their NC reasons; `flags` is an array holding `few_subjects` and `few_observations` (POP-COV-03, POP-EST-04). The header has none of these.
5. `options.exclude_subjects` (a list of labels, POP-DAT-01) is part of `options`.
6. `options.evaluate_only` is adopted: the engine runs the inner problems at the given parameters (θ = `initial`, Ω = `omega`, ξ = `error_init`), with no outer iteration and no covariance, status `evaluated`. The η̂ of an `evaluate_only` solve are polished (POP-INN-02).
7. The code list of `PopError` gains `unsupported_history` (POP-INN-03 items 6 and 7); the codes `unbounded_likelihood`, `non_positive_sigma`, `too_few_subjects`, `too_few_observations`, `inner_failed` and `invalid_option` are those of POP-INN-03.
8. `eta_shrinkage` is in the order of `random_effects`, with null where NC (POP-DIA-03); the EBE-based fields are null after an FO fit with the reason `fo` (POP-OBJ-03).
9. The values of `status` are those of POP-EST-03, plus `evaluated`.
10. The request carries the subjects inline; a dataset route builds the same list from the table (POP-DAT-01) and goes through the same function.
11. An infusion whose duration comes from the dataset (`pk1.iv_infusion`) needs the subject to carry the duration beside `dose`; the name (`duration`) is **assumed**, because no oracle case has one, and T-153 settles it with the first infusion case.
12. **Four more request keys, the oracle's own names (fix round of T-166).** `errors.json` uses three keys that the header of `oracle_pop.rs` does not list, and this item names them. **Decision taken meanwhile (2026-11-08), reversible by Abdou: the oracle's names are adopted, and POP-EST-02 is renamed to match (it said `fix`).**
    - `fixed`: a map from parameter id to the value it is held at, for typical values and error parameters (row `pr1_lag_fixed_at_first_time`: `{"tlag": 0.5}`). The parameter leaves φ (POP-EST-02);
    - `bounds`: a map from parameter id to `{lower, upper}`, either side optional (rows `pr1_lag_upper_*`: `{"tlag": {"upper": 0.5}}`), in the user's units, the bounds of FIT-BND-01 (POP-EST-02);
    - `dataset_file`: a path to a population table in place of `subjects` (row `pr6_dataset_refusal_addl`: `data/pop/errors/refuse_addl_3.csv`, no `subjects`). It is a table route: the loader builds `subjects` from the table (POP-DAT-01) and the request then goes through the same function as one that carries `subjects`; a request holds `subjects` or `dataset_file`, not both (a request with both is `invalid_option`, naming `dataset_file`, `assumed`);
    - `omega_shape`: `diagonal` or `block`, as in the header; it says how `omega` is read (a block Ω is estimated in full, a diagonal Ω has its off-diagonal zeros held) and is used by the oracle rows with a block Ω and by `pr5_unknown_omega_shape` (the value `banded`, refused as `invalid_option`, POP-INN-03 item 5).
13. **The names of Ω and ξ in `estimate` and `se`.** The header of `oracle_pop.rs` reads `estimate` and `se` by parameter id (`estimate["cl"]`), which covers the typical values and nothing else. For Ω and ξ the names already used by the sealed truth (`oracle/expected/pop/sealed/*.json`, key `truth`) are adopted, and `se` has the same keys: `omega_diagonal`, a map from random effect to variance (`omega_diagonal.cl`); `omega_full`, the matrix in the order of `random_effects` (in `se`, the standard error of each element, null for an element held at 0); `xi`, a map `a`, `b` in the user's units (`xi.a`, `xi.b`). In `se` an element is the standard error of the variance or covariance (POP-COV-04), of the printed kind. The second-look files use other names (`theta_hat`, `omega_hat`, `sigma_hat`, `respar`) for other tools' output and are not a model for the engine. Nothing in the oracle reads these keys yet (the sealed test asserts on the typical values only), so the choice is **`assumed`** and T-153 settles it with the first test that reads them.
