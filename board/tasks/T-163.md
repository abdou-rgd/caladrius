## Goal

T-150 reads a table in either layout into a dataset with several subjects. Nothing in the analyses uses that dataset yet: NCA and the fit still run on the worksheet's old path. Route the dataset into the analyses, engine side, as `specs/data.md` describes:

1. **NCA (DAT-USE-01).** `nca.run` with `subject = none` analyses every subject of the dataset, in both layouts, with one result or one error per subject. In the event layout a subject uses its observation rows and its first dose row, with the amount, time, duration (from `dur` or `rate`) and route. A subject with more than one dose row is refused for that subject only, with the sentence of DAT-USE-01.
2. **The individual fit (DAT-USE-02).**
   - The default stays as it is: with several subjects and none named, the fit is still refused with `subject_required`.
   - One value is added, `subject = all`: one independent fit per subject, with the same model and options and the initial estimates generated per subject. It returns a list of per-subject results, and an error in one subject is that subject's result.
3. **A refused subject (DAT-ERR-08).** An analysis of a subject that carries `refusal` is refused with the sentence of its check, while the other subjects run. This is what turns DAT-ERR-08 from `assumed` into something a test can check.
4. **The counts (FIT-ML-20).** The dataset layer supplies `n_used`, `n_missing` and `n_blq` to each fit result: `n_observations` is the `n_used` of the rule. Say whether the run layer's own counting stays, as a check, or goes.
5. **The covariates (DAT-USE-03).** They are copied into each per-subject result and used nowhere else.
6. **Three texts:**
   - the description of `data.import` (and of `data.describe` if it is affected), which must say what a multi-subject table gives;
   - the doc comment of `ColumnRole::ALL` in `crates/caladrius-project/src/worksheet.rs`, near line 59, where two sentences have lost their line break;
   - the CLI and MCP help for `subject = all`.
7. **The digest.** Existing steps must not move, since the default behaviour is unchanged. If any step moves, list it and explain why.
