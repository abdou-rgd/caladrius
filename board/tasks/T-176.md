  - In `crates/caladrius-engine/src/schema.rs:299-363`, the `FitOptions` definition is a closed object (`additionalProperties: false`, `schema.rs:63-75`). It lists:
    - `preset`, `derivatives`, `increment`, `criterion`, `convergence`, `max_iterations`;
    - `confidence_level`, `n_curve`, `fixed`, `bounds`, `flags`.

    It does not list `objective`, `error_model`, `error_init` or `information`, which `crates/caladrius-fit/src/lib.rs:147-157` reads.
  - In `schema.rs:406-418`, the status enum of `FitResult` lacks `exact_fit` (FIT-ML-15).
  - What was measured: in the `fit.run` entry of `caladrius-cli commands --format json` on 1ca5ade, `"objective"`, `error_model`, `exact_fit` and the word "likelihood" are all absent.
  - The engine does not check parameters against the schema when it runs a command, so the CLI runs. But an MCP client that reads the schema sees a closed `FitOptions` that has no `objective`, and it cannot ask for an ML fit.

## Goal

1. **The schema follows the code and `specs/fit.md` section 13.**
   - `FitOptions` gains:
     - `objective`, with values `ols` and `ml`;
     - `error_model`, with the values of FIT-ML-02;
     - `error_init`;
     - `information`, with its values.
   - Read the types, the defaults and the allowed values from `caladrius-fit` and `specs/fit.md`; never from memory.
   - The `FitResult` status enum gains `exact_fit`.
   - Every field that the ML fit adds to the result (for example `-2LL`, `AIC_ML`, `BIC_ML`, the error parameters and IWRES) appears under the name and type that the code serialises.
2. **A test that stops this from drifting again.**
   - In the engine's tests, build a `FitOptions` with every field set to a non-default value, serialise it, and check it against the published schema with the existing validator (`validate::check`).
   - Do the same for a `FitResult` of each status, including `exact_fit` and `at_bound`.
   - Choose how to build these values so that a field added later to `caladrius-fit` without the schema makes the test fail. If no such construction exists, say why in the report.
3. **The text.**
   - If the `fit.run` description or the help does not name the ML options, add one sentence that points to them.
   - No other text changes.

Nothing changes in `caladrius-fit`, `caladrius-models` or `caladrius-nca`. If the schema cannot be made true without a change there, stop and report it.
