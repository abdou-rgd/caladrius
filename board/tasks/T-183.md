- **Iteration:** T-178
- **Role:** interface
- **State:** in progress

## Goal

`apps/caladrius-tauri` opens a native window showing `apps/caladrius-front`, with the engine in the Rust process (`TauriTransport`, `engine_execute`), the same screens and numbers as in the browser.

1. `tauri.conf.json`: `frontendDist` -> `../caladrius-front/dist`; add `devUrl` `http://127.0.0.1:5173` for development; window size 1440x900, min 900x600; keep the CSP (`wasm-unsafe-eval` stays: the page instantiates the module for formatting).
2. The page in Tauri still loads `pkg/` for the formatter and must not start the worker. Check `src/engine.ts` of the front does this.
3. One command to open the window: `npm run desktop -w @caladrius/front` (script `scripts/desktop.mjs`: build the wasm if missing, `vite build`, then `cargo run --release --manifest-path apps/caladrius-tauri/Cargo.toml`), honouring `CARGO_TARGET_DIR`.
4. Update the module comment of `apps/caladrius-tauri/src/lib.rs` (no longer a placeholder page) and the shell's tests if they reference the prototype.
5. Linux: if the window is blank under WebKitGTK (known DMA-BUF/compositing issue), set `WEBKIT_DISABLE_DMABUF_RENDERER=1` in `main.rs` only when the variable is not already set, with a comment, and say so in the thread.

## Allowed files

`apps/caladrius-tauri/**` (not `gen/` by hand: it is regenerated), `apps/caladrius-front/scripts/desktop.mjs`, `apps/caladrius-front/package.json` (the script only), `apps/caladrius-front/src/engine.ts` only if point 2 needs it, this card.
