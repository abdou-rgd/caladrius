# T-153: the population objective at fixed parameters (FOCEI, FOCE, FO), the conditional modes

- **Role:** engine
- **State:** in progress
- **Iteration:** T-139
- **Depends on:** T-162 and T-166 (`specs/population.md`), T-152 (the failing tests)
- **Source:** `specs/population.md`, the T-139 plan (wave 7), and the T-152 review.

## Goal

Implement the population objective of `specs/population.md` at **fixed parameters**, with no outer iteration. It covers the inner problem, the conditional modes η̂ and the three methods. The estimation, the covariance and the shrinkage are T-154, and the diagnostics are T-155.

1. **The model layer:**
   - the catalogue models the oracle uses (`pk1.iv_bolus`, `pk1.oral_1`, `pk2.iv_bolus`) with log-normal random effects (POP-MOD);
   - the test-only model `identity_linear` (POP-MOD-05), which the request names and the oracle uses. It must not be reachable from the user commands.
2. **The inner problem:** for each subject, the conditional mode η̂ that minimises the individual objective of POP-OBJ.
   - Use a safeguarded Newton step, then polish by Newton (H37), so that η̂ is within `POP_ETA` of the reference.
   - The case `int_iv_comb_q1_large` has a region that curves the wrong way away from the mode. The T-152 review showed that a safeguarded Newton step is enough there.
   - A subject whose inner problem fails gives `inner_failed`. Test it with an injected failure in a unit test (the T-152 review's answer).
3. **The objectives:**
   - FOCEI (`foce_i`, the default);
   - plain FOCE (`foce`), with σ frozen at the population prediction (POP-OBJ-06);
   - FO (`fo`), which has no conditional-mode quantity (POP-OBJ-03).
   - Both OFV conventions (`full` and `no_2pi`, POP-OBJ-05), with the total and the per-subject values.
4. **The request and the answer:** the vocabulary of POP-API-01 and the header of `crates/caladrius-fit/tests/oracle_pop.rs`, with `options.evaluate_only = true`.
   - The answer gives `ofv`, `subjects[].ofv` and `subjects[].eta_hat`.
   - Where Ω is given as a vector, its order is the lower triangle by rows. The simulator (T-159) uses the same order.
5. **Refusals:** every refusal of POP-INN-03 that is decided before any outer iteration, with the code and sentence of the spec. A refusal that needs the fit itself waits for T-154; name each one in the report.
6. **The adapter:** replace the body of `population_fit` in `crates/caladrius-fit/tests/oracle_pop.rs` and nothing else in that file or in the other test files.
