## Goal

A reusable table component, `@caladrius/table`, that every result table of the interface uses: NCA parameters, fit estimates, diagnostics, and later population tables. It renders engine answers as they are and never computes, rounds or formats a number itself.

1. **Package `apps/caladrius-table/`** (TypeScript, React 19 as a peer dependency). It is built on `@tanstack/react-table` 9.3.1 and `@tanstack/react-virtual` 3.14.26, pinned exactly, lock file committed.
   - TanStack Table **v9** has a different API from v8, which most examples and models know. Read the v9 documentation and say in the thread which v8 habits did not apply.
2. **Input.** One description of the table: columns (id, label, unit, kind `number | text | flag`, optional width, frozen or not) and rows of raw values, as the engine returns them (numbers as `f64`, `null` for absent). The component receives a `Formatter` from `apps/caladrius-bridge/ts/src/format.ts` and formats every number through it at render time.
   - No `toFixed`, `toPrecision`, `Intl.NumberFormat`, `Math.round` or string concatenation of a number anywhere in the package. A test greps the sources to enforce it.
   - A change of `Display` (digits, decimal comma) re-renders every visible cell without a call to the engine.
3. **Features of level 1:**
   - Row and column virtualization: 100,000 rows × 20 columns stay smooth (completion criterion below).
   - Sorting by one or several columns, on the **raw values**, never on the formatted text. The order of non-finite values and `null` is defined: they always go last, whatever the direction, and a test checks it.
   - A text filter per column and a global one. They match the **displayed** text, so what the user reads is what is filtered.
   - Frozen columns on the left (the subject or parameter column), resizable and reorderable columns, and column visibility.
   - Visual grouping by a text column (for example, by subject or treatment), folded and unfolded. **No aggregation**: the TanStack aggregation functions stay off, and a group header shows its label and its row count only. A summary row (a geometric mean, a CV%) is an engine command, never the table.
   - Selection of rows and of a single cell, with keyboard navigation (arrows, Home and End, Page Up and Page Down, Ctrl+Home). The focus is visible.
   - Copy: the selected rows or cells as TSV with a header row, as `ResultsPanel` does today. A second action, "copy exact values", uses `Formatter.exact`, so that pasting into R or Excel loses no digit.
   - Flags: a row or cell flagged by the engine (for example, an NCA quality flag) shows its mark and the engine's sentence as a tooltip, as in `ResultsPanel`.
4. **Look.** The colours, spacing and font come from the CSS variables built from `theme.json` (`build/theme-css.mjs`). There is no CSS framework and no icon set. The rendering is light and dark, and dense or comfortable through one variable.
5. **Accessibility.** The ARIA grid pattern: `role="grid"`, `aria-rowcount` and `aria-rowindex` under virtualization, `aria-sort` on sorted headers, and the selected cell announced.
6. **Rule 6 (never crash).** An empty table, a column missing from a row, a `NaN` or a 200-character label all render a sentence or a dash, never a thrown error. An error boundary around the table shows a sentence if rendering fails.
7. **Integration.** `ResultsPanel` of `apps/caladrius-proto-react` uses `@caladrius/table` for its two tables (headline and all parameters). It shows the same 151 cells, with the same texts and the same seal as before (the T-136 check), and its copy gives the same TSV.
8. **A demo page** (`apps/caladrius-table/demo/`, served by Vite) shows:
   - an NCA results table from a recorded engine answer (fixture);
   - a synthetic table of 100,000 × 20 for the measures. The synthetic values exist only in the demo and the tests, never in the app.

## Out of scope (later cards)

- **Level 2: range selection and clipboard.** Selection of rectangular ranges with the mouse and Shift+arrows, copy of a range as TSV, Excel-compatible. Front only.
- **Level 3: spreadsheet-like data entry.** Editing, pasting a range from Excel, adding rows and columns. Every change is an engine command, and undo goes through the engine history. The engine has `data.set_cell` and `data.set_column`. A paste of a range needs one command for many cells (for example `data.set_cells`), so that it is one history entry. That is an engine card first, then this level.
- Export to xlsx: through `export.table` in the engine or the shell, never built in the front.
- Summary rows (mean, geometric mean, CV%, by group): engine commands, shown by the table as ordinary rows.
