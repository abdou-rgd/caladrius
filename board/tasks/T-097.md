# T-097: Import: read below-the-limit text cells (`< LQ`, `BLQ`, `<LOQ`...) as BLQ points

- **Role:** interface (caladrius-project import, caladrius-engine fit data), reader (spec rule)
- **State:** to review
- **Depends on:** none
- **Source:** out-of-sample coursework test of 2026-10-21 (data kept outside the repository; only the finding is recorded here): a concentration table that writes a value below the limit of quantification as the text `< LQ` cannot be imported as data

## Goal

Today one text cell such as `< LQ` turns the whole concentration column into text (`crates/caladrius-project/src/csv.rs` `type_column`), the column loses its role and every analysis is refused. Laboratory tables write values below the limit of quantification this way, so the file has to be edited by hand before Caladrius can read it.

The import must recognise the usual below-the-limit spellings in an otherwise numeric column, keep the column numeric, and carry the information to the analyses with one written rule:

- the cell is stored as 0, the BLQ convention of the NCA (NCA-DAT-05), and the row is flagged BLQ on the column;
- the NCA then treats it through its BLQ policy (`options.blq`, NCA-DAT-06), unchanged;
- a fit leaves BLQ rows out, like missing rows, and counts them (`n_blq`), so a 0 is never fitted as a measured value;
- the import notes say how many cells were read as BLQ and with which spelling; editing such a cell clears its flag.

## Allowed files

`crates/caladrius-project/src/{csv.rs,worksheet.rs,tests.rs}`, `crates/caladrius-engine/src/{run.rs,commands/data.rs,commands/analysis.rs,schema.rs,tests.rs}`, `crates/caladrius-project/src/analysis*.rs` (the fit result counter), `specs/nca.md` (new rule NCA-DAT-05c), `specs/fit.md` (BLQ rows left out), the card.

## Completion criterion

`cargo test -p caladrius-project -p caladrius-engine` passes with new tests: each recognised spelling (with spaces, any case, decimal comma) gives a numeric column with the right BLQ rows; a column with an unrecognised text stays text as before; NCA on a synthetic profile with a trailing `< LQ` equals the NCA of the same profile with 0 written; a fit leaves the BLQ row out and reports `n_blq` 1; a project file without BLQ flags loads unchanged. `cargo clippy --workspace --all-targets -- -D warnings`, `cargo xtask layers`, `cargo xtask lint` green.
