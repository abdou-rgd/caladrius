# T-181: The fit slice: data, model (1, 2 or 3 compartments), initial estimates with a live preview, fit, results

- **Iteration:** T-178
- **Role:** interface
- **State:** to review
- **Depends on:** T-180

## Goal

From data to a fitted three-compartment model on one screen, every number from the engine.

1. **Data panel.** Import a CSV (file picker and drag-and-drop) or one of the samples (`data/pk3_iv_bolus.csv`, `data/theoph.csv`, `data/indometh.csv`): `data.import { name, csv }`; the engine's notes (units read from headers) and unit warnings shown. The worksheet shown in `@caladrius/table` (columns and units from the answer's `worksheet.columns`; the rows from `data.preview { csv, rows: 200 }` for now, said in a note under the table when the worksheet has more rows; reading the whole worksheet is a later engine command, not front parsing). Subject picker from `worksheet.subjects`. The raw plot: `plot.xy { worksheet, layout: 'overlay', scale: 'both' }` then `plot.scene { analysis }`, drawn by `PlotView`; re-run with `analysis` to update instead of creating new objects.
2. **Model panel.** Model chosen in three steps: compartments (1, 2, 3), route (IV bolus, IV infusion, oral first order, oral first order with lag, oral zero order, oral zero order with lag), then the parameter set. The model ids come from the `ModelId` enum of `fit.run`'s `params_schema` in `describe()`; a model the engine does not list is not offered. The parameter names of each set are UI knowledge kept in one data file `src/model/parameterSets.ts` (from the `ModelId` description: pk1 `v` with `cl` or `k`; pk2 `cl,vc,q,vp` or `k10,k12,k21,vc`; pk3 `cl,vc,q2,vp2,q3,vp3` or `k10,k12,k21,k13,k31,vc`; plus `ka`, `tlag`, `dur` by route; leave out the `a,b,alpha,beta` macro sets tonight), with a comment that an engine command describing models should replace it (bolder step). Labels and units via `Formatter.parameterLabel` / `parameterUnit` (with the worksheet's `derived_units`). Weighting from the `Weighting` enum (default `inv_y2`, the engine's labels if any, else the ids). Dose: from the data (shown from `fit.evaluate`'s answer) or typed.
3. **Initial estimates with a live preview.** One input per parameter; parsing with `Formatter.parseNumber` (accepts the decimal comma). When every value is a finite number, debounced (150 ms) and latest-wins (drop answers of superseded requests): `fit.evaluate { worksheet, subject, model, initial, weighting }` (shows the WRSS at the start and the dose), then `model.simulate { model, dose, params: initial, grid: { start: 0, end: <x max of the raw plot's linear panel>, points: 200 } }`, drawn as `PlotView`'s `overlay` on the subject's plot (both panels). A refusal shows the engine's sentence under the inputs. For pk1 only, an "Estimate" button calls `fit.initial_estimates`; for pk2/pk3 the engine refuses it, so the panel says "enter a value for each parameter" instead.
4. **Fit.** "Fit" runs `fit.run { worksheet, subject, model, initial, weighting }` (re-run with `analysis` to update the same object). Then `plot.xy { fit, view: 'profile', scale: 'both' }` and `plot.xy { fit, view: 'weighted_residuals_time', scale: 'linear' }`, each followed by `plot.scene`, shown in the Plot panel as tabs or stacked (Fit, Residuals, Data).
5. **Results panel.** Summary first: status sentence (`status_message`), flags (`flag_messages`), then the estimates table in `@caladrius/table` (Parameter with its label and unit, Estimate, SE, CV%, CI low, CI high; the keys of `outcome.ok.values` are `<name>`, `se.<name>`, `cv.<name>`, `ci_lo.<name>`, `ci_hi.<name>`; read `apps/caladrius-table/test/fixtures/fit_pk3_A.json` and, for the same mapping in the egui app, `crates/caladrius-ui/src/fitresult.rs`), a CV% over the engine flag threshold flagged by the engine's flags only (the front does not compare numbers), then diagnostics (WRSS, AIC, SBC, condition number, … the scalar keys) in a second table, details folded. Under the results, the seal: short sha256, engine version, and "copy seal". A stale result (input changed after the fit) shows a stale badge (use the `status` of `plot.scene` and `project.describe`).
6. **History panel:** the log of T-180 (command, ok or the error code, short seal), newest first.
