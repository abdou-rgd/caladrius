## Goal

The app every later screen lives in, runnable tonight with `npm run dev`:

1. **Build.** Vite 8 + React 19 + TypeScript strict, in the npm workspace `apps/` (its `package.json` is already there with pinned dependencies; `scripts/build-wasm.mjs` builds the engine into `public/pkg/` and copies the sample CSVs into `public/data/`: make it copy only `*.csv` from `samples/`). Reuse, adapting, the files of the React prototype of T-136 (read them with `git show origin/iter2/react:apps/caladrius-proto-react/<path>`): `vite.config.ts` (theme plugin `virtual:theme.css`, alias `@caladrius/bridge-client` to `../caladrius-bridge/ts/src/index.ts`, `worker.format: 'es'`, `server.fs.allow` the repository), `build/theme-css.mjs`, `tsconfig.json`, `src/engine.ts` and `src/engine.worker.ts` (WorkerTransport in a browser, TauriTransport when `__TAURI_INTERNALS__` is present, `createFormatter` on the same compiled module).
2. **Session store** (`src/session/`): one plain TypeScript store (no state library; `useSyncExternalStore`) holding what the engine answered (worksheets, analyses, last answers with their seals) and the UI state (selected subject, model, initial values, display settings). Every engine call goes through one function `run(command, params)` that records the answer (command, ok, seal, error) in a small in-memory log shown in a "History" panel. The store is serializable (rule 7): no class instance or function in the state.
3. **Layout** with dockview (`dockview-react`): panels Data, Model, Plot, Results, History; the layout is saved to and restored from `localStorage` (Rerun-style blueprint, data not code); a "Reset layout" action.
4. **Top bar:** the app name, the worksheet name, a display menu (significant digits 2 to 8, decimal comma; this is the `Formatter.setDisplay`; changing it re-renders every number without an engine call), light/dark/system theme, and the engine status (loading, ready, error with its sentence).
5. **Command palette** (minimal, the full one is T-186): `cmdk` opened by Ctrl+K / Cmd+K (`tinykeys`), listing the engine commands from the bridge's `describe()` (title and id) plus the app's own actions (reset layout, theme, import a sample). Choosing an engine command that takes no required parameter runs it and shows its answer JSON in the History panel; others show their description and example (the form generator is T-186).
6. **Errors** (rule 6): an engine refusal shows the engine's sentence where the action was taken; a transport failure shows a sentence in the top bar; an error boundary per panel.
7. **Look:** CSS variables from `theme.json` only (the same names the table and plot packages read: `--c-*`, `--space-*`, `--font-*`, `--radius-*`, `--size-*`); system fonts; light and dark; no CSS framework, no icon font.
