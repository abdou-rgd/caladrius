## Goal

The protocol exists on paper; nothing generates the confirmation exercises or runs them on several seeds. Build:

- a deterministic generator of the demo tier: 40 synthetic exercises, each its own draw (family, units, time unit, BLQ, parameters, sampling, noise), seed 20261021, never the development seed, gold computed with `options.units`, each `meta.json` tagged `frozen` so `run_bench.py` refuses it;
- the wordings format of §5.3 (placeholders, validation, seeded draw), without writing or reading any wording;
- a runner: one tier x one gate x seeds, the seed sent in each request, a manifest check before the first exercise, an exercise-level failure kept as 8 ERROR turns, a replay mode (§10.1), the same runner on the development set for the gate decision of §8;
- a stub model standing in for llama-server, so the whole pipeline (client, engine, both gates, rubric, report, analysis) runs in the cloud without a GPU.
