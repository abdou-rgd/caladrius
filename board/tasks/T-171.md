## Goal

1. **A subnormal a + b + c** (`params3.rs` around lines 484-490, `unit_scale`).
   - Today: when T = a + b + c is subnormal, the factor is 1, the double-double path underflows, and the set is refused as `DegenerateExponents` "the poles … cannot be told apart". That reason is false.
   - The reviewer measured this on `base` at ×2^−1023 down to ×2^−1070, and on `edge_tau` at ×2^−1030.
   - Choose one of the reviewer's two fixes and say why:
     - (1) for a subnormal T, return 2^1022 (`f64::from_bits(2045 << 52)`), which is exact, and restore the 2^−1000 case of the scale test;
     - (2) refuse upstream: a + b + c must be a normal number, else `DerivedOutOfRange` "rescale the parameters".
   - Either way, add a unit test with a subnormal a + b + c that asserts the outcome.
2. **Derived quantities that are not normal numbers.**
   - Today: with the exponents of `base` scaled by λ×1e−103 to ×1e−107, intermediate products (αβγ, the triple offset product) go subnormal before any check fires. A wrong number comes out with no refusal. The reviewer measured k10 errors of 2.0e−14 at ×1e−103 and 1.2e−2 at ×1e−107; the refusal only comes at ×1e−110 (`k10 = 0`).
   - Make `derived` (or the checks on the macro path) refuse a value whose magnitude is below `f64::MIN_POSITIVE`, as `DerivedOutOfRange` with the `short` printing. Check the intermediate products that can go subnormal, not only the final constants.
   - **Find where `derived` is used.** If it is shared with pk1 or pk2, the change must not move any oracle row, conformance value or digest number. If it would, stop and report instead of changing it.
   - Add a unit test at λ×1e−105 that asserts the refusal.
3. **Remove the dead arm** "its coupling is not a positive number" (params3.rs:398), which the review found unreachable.
