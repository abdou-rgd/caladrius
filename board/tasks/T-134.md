# T-134: The engine bridge: one call, two transports and shared number formatting

- **Role:** interface
- **State:** in progress
- **Iteration:** T-130
- **Depends on:** T-131
- **Source:** iteration 2 (T-130), wave 2; the section Platform code of `docs/interface-inventory.md`.

## Goal

A web front reaches the engine through one call: `execute(command JSON) -> sealed answer JSON`. That call runs over two transports, a Web Worker that runs the engine in wasm and a Tauri command on the desktop, and both return the bytes the engine returns in Rust. The same bridge gives the number formatting of the current interface, so that no front formats a number its own way.

1. **`crates/caladrius-format`** (new, layer L1, no dependency apart from `libm`): `crates/caladrius-ui/src/fmt.rs` moved there.
   - Same functions and same outputs. The standard `log10` and `floor` become `libm`, as the rule-10 lints ask of a new crate.
   - Every formatting function also exists with an explicit `Display` (digits, decimal comma), for a caller that has no thread-local setting.
   - `caladrius-ui` re-exports the crate as its `fmt` module, so no call site and no snapshot changes.
2. **`apps/caladrius-bridge`** (new, app layer, in the workspace; `rlib` and `cdylib`).
   - A Rust type that owns one `Engine` and has the single call: a request `{"command": id, "params": ...}` as text in, an answer as text out. The answer is one fixed shape for success and failure: the answer or the error of `Engine::execute`, plus the seal of the history entry that the command just recorded (`engine.history().entries()`), since `execute` does not return it. The shape is documented in the crate's doc comment; wave 3 builds on it.
   - With `wasm-bindgen`, under `cfg(target_arch = "wasm32")`: that call, the formatting functions, and `describe()`.
   - `project.load` and `project.replay` stay out of the bridge for now (they reach the engine through `Engine::load_bytes` and `replay_bytes`); say so in the doc comment.
3. **The TypeScript client**, `apps/caladrius-bridge/ts/`.
   - An `EngineClient` interface with two transports: `WorkerTransport` (a Web Worker that loads the module built with `wasm-bindgen --target web`) and `TauriTransport` (`invoke`).
   - Formatting is synchronous on the page: a React cell cannot wait for a worker. Either the page instantiates the module a second time for formatting, or a smaller module is built from `caladrius-format` alone. Pick one and give its size in the thread.
   - npm brings `typescript` and `@tauri-apps/api` and nothing else. The tests use `node:test`. `package-lock.json` is committed.
4. **`apps/caladrius-tauri`**, a minimal Tauri 2 shell.
   - It is excluded from the workspace (`exclude` in the root `Cargo.toml`), has its own `Cargo.lock`, and depends on `caladrius-bridge` by path. CI and clippy on the workspace stay as they are.
   - One command, `engine_execute`, and one capability that allows only it.
   - The window shows a placeholder page from `frontendDist` that calls the engine once and shows the sealed answer.
   - It is launched with `cargo run --manifest-path apps/caladrius-tauri/Cargo.toml`. The Tauri CLI is not needed; if the Windows icon needs it, `cargo install tauri-cli` is allowed (MIT or Apache-2.0).
5. **The same-bytes check**, `cargo xtask bridge`.
   - A fixed script of requests, committed as a file:
     - the import of `oracle/data/edge_blq.csv`;
     - `nca.run` on subject 3;
     - `plot.xy` and `export.plot`;
     - `history.list`;
     - an unknown command and invalid parameters.
   - It runs the script three ways: through `Engine::execute` in Rust, through the wasm module under Node (as `xtask/src/digest.rs` does), and through the Tauri command handler called directly in a test of the shell, without a window.
   - It compares the answers byte for byte and prints `bridge: k of n answers identical on 3 transports`.
   - A clock or provenance that differs between runs is turned off in all three runs, and the thread says which.

## Completion criterion

- `cargo xtask bridge` prints `bridge: n of n answers identical on 3 transports`, with n at least 7.
- `cargo test -p caladrius-ui` passes with every snapshot unchanged, and `cargo test -p caladrius-format -p caladrius-bridge` passes.
- `cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt --all --check`, `cargo xtask layers`, `cargo xtask lint`, `cargo xtask review` and `cargo xtask wasm` pass.
- `cargo test --manifest-path apps/caladrius-tauri/Cargo.toml` passes, and `cargo run` of the shell starts on this PC and stays up for ten seconds without an error. Looking at its window is for wave 3.
- `cd apps/caladrius-bridge/ts && npm ci && npm test` passes.
- The thread gives the sizes: the wasm module (from `wasm-bindgen`, without `wasm-opt`, which is not installed), the formatting module if separate, and the Tauri executable in release.
