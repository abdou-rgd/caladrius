## Goal

Implement in `caladrius-fit` the engine side of `docs/long-running-commands.md` section 2, and nothing above it: no `caladrius-engine`, no CLI, no bridge (T-146 does those).

1. **A stepper that owns its state.** `FitRun<M: FitModel>` owns its model by value, with a blanket `impl FitModel for &M`, so that `run_model(&dyn FitModel, &FitInput)` keeps its signature and its test callers, and a host that needs `'static` passes a `ModelId` by value (another way is allowed if `run_model` keeps its signature and there is one loop). It holds everything today's loop carries across iterations: the iterate, the predictions, the weights, λ, the trace, the previous decrease of FIT-CNV-05, the status, the starting weighted sum of squares, the gain floor, and anything else the loop carries; forgetting one breaks rule 10. The block after today's loop (the rollback to the best iterate, then `result::build`) belongs to the step that returns `Finished`. `step` runs exactly one iteration of today's loop in `engine.rs` (the same line search, the same Jacobian, the same stopping tests) and returns either the progress of that iteration or the finished `FitResult`. `step(&mut self) -> Step<'_>` may borrow the stepper; the page's sketch is a shape, not a signature to copy. The refusal of mutating commands while a job runs is T-146's (`caladrius-engine`), not this card's.
2. **An observer.** After each committed iteration (iterate and trace row written, before the next iteration begins) the loop hands the observer the iteration number, the objective (WRSS today) and the named parameters, and reads back continue or cancel. Never inside the line search or the Jacobian.
3. **One code path.** `solve()` becomes `run` with an observer that never cancels. Every existing test of `caladrius-fit` passes unchanged, and every fit number in `docs/conformance.md` is the same bit for bit (`cargo xtask conformance && git diff --exit-code docs/conformance.md`).
4. **Cancel is a sentence.** `run` returns `Done(FitResult)` or `Cancelled { after_iteration, trace }`, the trace holding the rows of FIT-OUT-11 from iteration 0 to `after_iteration`. A cancel before the first iteration gives `after_iteration` 0 and the row of iteration 0. No `unwrap`, `expect`, indexing that can panic, or `panic!` on any path (rule 6).
5. **Tests that prove it** (in `crates/caladrius-fit/src/` or `tests/`):
   - a recording observer that never cancels: the `FitResult` is equal field by field and bit for bit to `solve()`'s, on the oracle fit cases already in the crate's tests (at least one per model family used there, among them a case that stops on the iteration limit and one that fails);
   - a loop of `step` until `Finished` gives the same `FitResult` as `solve()`;
   - cancel at iteration n for several n (0, 1, the last but one) returns `Cancelled { n, trace }` with n + 1 trace rows equal to the first n + 1 rows of the uncancelled run;
   - the observer sees iterations strictly increasing from 1, and the objective it sees equals the trace row.
6. **Rule 9.** `cargo xtask wasm` still compiles; `cargo xtask digest` gives the same line as on `iter3/base`.
