## Goal

Build the NCA screen of the shared brief in Leptos 0.8, client-side rendered: Rust compiled to wasm, with the DOM and the plot as SVG drawn from `plot.scene`.
- **Engine.** It is linked into the same wasm and called in process through `caladrius_bridge::Bridge`, with no worker and no JSON round trip through JavaScript. This is the point of the candidate: one language from the engine to the screen.
- **Tauri.** The same build runs in a browser and as the `frontendDist` of the Tauri 2 shell of `apps/caladrius-tauri`. In the shell the engine stays in the wasm; the shell only gives the window and the measure commands.
- **Branch.** It runs on branch `iter2/leptos`, made from `iter2/react`, so the shell already has the webview-folder fix and the measure commands of T-136. The worktree is `C:\Users\abdou\caladrius-iter2\leptos`.
- **Measure definitions.** Same as T-136, so the two webview prototypes compare directly:
  - `input_to_paint_ms` runs from the handler call to the first frame after the new state is rendered (a `requestAnimationFrame` callback, then a message);
  - `frame_ms` is the interval between that frame and the one before it;
  - the cells checked are the same cells as T-136, headline and "All parameters".

Dependencies: `leptos` 0.8 (feature `csr`), `wasm-bindgen`, `web-sys`, `serde_json`, and the workspace crates. Nothing else unless the thread says why. There is no CSS framework, no chart crate, no web font and no icon set. The colours come from `theme.json` as CSS variables. Build with `trunk` (`cargo install trunk` is allowed: MIT OR Apache-2.0) or with the `wasm-bindgen` CLI already used by `cargo xtask bridge`; say which in the thread.
