## 3. Spec against code

Matches: `more_than_one_dose` (code, sentence); combined sigma = sqrt(a*a + b*b*c*c), which Rust evaluates as a*a + ((b*b)*c)*c; y = c + s*z; proportional and combined_sd; the canonical layout (six line kinds, field order, `none` for no LLOQ, P by BTreeMap order, `{rep}|{id}|...`); defaults (`omega_shape` diagonal, `replicates` 1, `negative` keep, quantiles 0.05/0.5/0.95); the order of checks in `Study::build` (seed, design, model, lloq, quantiles, replicates, error model, random effects); `simulate` stops at the lowest cell index.

Silent or partial mismatches:

- F1 (minor). SIM-DET-04 says an integer is written "without sign or leading zero" and lists only `rep`, `obs`, `cens` and the counts. The seed on line 1 is a u64 in decimal; it is covered by line 1's "(the seed as a decimal integer)". No mismatch, but the label rule "written as it is held" is the only description of `id`; fine.
- F2 (minor, code side, not a spec defect). OS-14 reports that the comment in `study.rs:124` says "The design first" while line 123 checks the seed first. The spec records it as an open item, good. The comment is wrong against both the spec and the behaviour. Smallest fix: a code card that corrects the comment (no behaviour change); not for the reader.
- The "inside one cell" order of SIM-DET-01 (parameters, model, IPRED, sigma, y) matches `evaluate`/the checks after it as far as I read; I did not trace the model-refusal path.

All differences that I found are either written as open items (OS-12, OS-13, OS-14) or are the code comment above.
