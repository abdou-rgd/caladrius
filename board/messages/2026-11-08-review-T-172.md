## Blocking

### F1. A `pk3.iv_infusion` fit on an event table does not take the duration of the dose row

- `crates/caladrius-engine/src/run.rs:332-334`:
  ```rust
  fn takes_dose_duration(model: ModelId) -> bool {
      matches!(model, ModelId::IvInfusion | ModelId::Pk2IvInfusion)
  }
  ```
  The doc comment above it says "an intravenous infusion"; `specs/data.md` DAT-USE-02 (line 235) says the fit "takes the dose and its time and duration from the subject's dose row". This function came from the ML side (T-163, 1e7b365), before pk3 existed; the pk3 side added `ModelId::Pk3IvInfusion` to the catalogue (`crates/caladrius-models/src/model.rs:95`) and the merge joined the two without a conflict, so no one added the pk3 id. The six pk3 ids are routed everywhere else (`crates/caladrius-fit/src/initial.rs:168-173`, `crates/caladrius-fit/src/model.rs:198`, `crates/caladrius-engine/src/schema.rs` `THREE_COMPARTMENT`), only this `matches!` was missed.
- Measured (CLI built from 1ca5ade, event-table CSV `pk3_inf_event.csv` with one dose row `amt 100, dur 1` and 18 observations simulated by `model.simulate pk3.iv_infusion`):
  - `fit.run --param model=pk2.iv_infusion` (initial cl, vc, q, vp): exit 0, status `converged`, `dur` taken from the file.
  - `fit.run --param model=pk3.iv_infusion` (initial cl, vc, q2, vp2, q3, vp3): exit 1, `error: fit_error: initial estimates: model pk3.iv_infusion needs the parameter `dur`; give its value`.
- The `FIT_RUN` description (`crates/caladrius-engine/src/commands/analysis.rs:341`) says "For an infusion model (pk1.iv_infusion, pk2.iv_infusion) on an event table, `dur` is held at the duration of the subject's dose row", so the published text agrees with the code and not with the spec; it must change with the code.
- No wrong number is produced (the fit is refused readably, and `options.fixed.dur` works around it), so this is a routing gap at the meeting point, exactly the case the card's fourth rule names. Fix: add `ModelId::Pk3IvInfusion` to the `matches!`, name pk3 in the `FIT_RUN` sentence, and add a routing test beside the pk2 one in `crates/caladrius-engine/tests/population_routing.rs`.
