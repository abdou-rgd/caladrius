## 1. Spec fidelity of the numerics: faithful

- `rng.rs:23-34`: the round is `(hi1 ^ c1 ^ k0, lo1, hi0 ^ c3 ^ k1, lo0)` with `mulhilo(M0, c0)` and `mulhilo(M1, c2)`; round 0 uses the key as given and the key is bumped by `(W0, W1)` after each round, 10 rounds: SIM-RNG-01 as written. The three known answers pass (`tests.rs:47`), and the oracle's 37 streams pass.
- `rng.rs:148`: `((word >> 12) as f64 + 0.5) * f64::EPSILON`, exactly SIM-RNG-04; no `powi`, no `mul_add` anywhere in `sim/` (grepped).
- `normal.rs:80-96`: `|q| <= 0.425`, `rho = 0.180625 - q*q`, `(q * poly(rho, A)) / poly(rho, B)` in that order; tails with `libm::log`, IEEE `sqrt`, split at `t <= 5.0`, `t - 1.6` and `t - 5.0`, sign restored last. `poly` is Horner from c7 down (`fold(0.0, acc*x + ci)`; the first step is `0*x + c7 = c7`, exact). Transcendentals: `libm::log` and `libm::exp` only; `abs`, `sqrt`, `floor`, `ceil`, `fract` are exact.
- `omega.rs:68-91`: Cholesky-Banachiewicz row by row, `T` accumulated left to right and subtracted once, pivot test `s.is_finite() && s > 0.0` before `sqrt`, `L_ij = s / L_jj`. `apply` (93-104) accumulates `eta_i` from 0 left to right in j. `study.rs:417`: `theta * libm::exp(eta_k)`.
- `result.rs:302-313`: type 7 in the spec's exact form `(1 - g) x_lo + g x_hi`, sort by `total_cmp`.

Note (no fix needed): `study.rs:444`, `combined` is `(a*a + b*b*c*c).sqrt()`, evaluated as `((b*b)*c)*c`; the spec writes b²·IPRED². Both are deterministic and the difference is one rounding inside a tolerance target; I record it so nobody later "fixes" it silently and moves the digest.

## 2. Determinism: sound

- A cell (`study.rs:360-373`) uses only `(seed, replicate, label key)` and the plan of its own subject. No `HashMap`, no clock, no thread, no global in `sim/` (grepped). Parameters are a `BTreeMap`, so the subject table and the canonical text list P by name in a fixed order.
- `assemble` (`result.rs:162-177`) refuses a wrong count and any cell whose `(replicate, subject)` is not its index; `sim_threads.rs:103-115` proves both refusals. The thread test uses 1, 3, 4, 7 and 128 threads on 91 cells, strided and blocked, joined in reverse order: the "does not divide" and "larger than the count" cases of SIM-DET-02 are both covered.
- Canonical text (`result.rs:319-383`): `{x:?}` is Rust's own shortest round-trip formatting, the same on wasm; headers, counts, the two tables and the summary, one row per line. Well defined. Two notes: a label containing `|` or a newline makes the text ambiguous to a reader (still deterministic); the dataset table of SIM-OUT-02 is not in the text, which matches the spec's "tables of SIM-OUT-01 and the summary".

Note (`result.rs:153-156`, `sim_threads.rs`): when several cells would refuse (`non_finite_value`, `model_refused`), the sequential run names the lowest index and a threaded caller names whichever its threads met first. The library returns no partial output either way, but the refusal *sentence* can differ with the thread count. If an error is to be "the same answer" under SIM-DET-02, the caller must report the lowest failing index. A note for the future `sim.run`.

## 3. Refusals: complete, one ordering remark

All codes of SIM-REF-01 to -06 exist (`error.rs:11-38`) and the 49 refused rows plus their controls pass. Nothing is refused after output starts: `simulate` collects cells with `?` before `assemble`; the per-cell refusals (`study.rs:420, 425, 454`) check P, then the model, then IPRED, σ and y for finiteness, and the oracle's `non_finite_value` row (Ω = 1e8 on `cl`) is caught at the parameter stage with the spec's words "in subject 3, replicate 0, with cl".

Note (`study.rs:119-122`): `missing_seed` is checked before the design, while the card's item 6 says `label_key_collision` and `duplicate_times` are "checked on the design first". The spec itself ranks nothing, and the oracle rows have one cause each, so nothing fails; a request with no seed and a duplicate time gets `missing_seed`. Acceptable; recorded.

## 4. The adapter (`oracle_sim.rs:75-386`): translates honestly, with two things it should not do

- `threads` is accepted in the allow-list and never reaches the engine (line 177); the answer cannot echo it since `SimInput` has no such field. The invariance rows `threads_2/7/64/default` pass.
- No error code is remapped (`lift` copies `code.as_str()` and the message). An unreadable number becomes NaN (`num`, line 86) so that the engine's own finiteness check names the field; a NaN cannot pass into a passing comparison because the engine refuses it. Nothing is swallowed.
- **Should-fix** (`oracle_sim.rs:360-367`): the adapter refuses `replicates < 1` itself ("replicates {v} must be an integer from 1") before the engine. The engine's own check (`study.rs:146-148`) is therefore never exercised by `replicates_zero`; that row tests the adapter. Smallest fix: only refuse what `u64` cannot hold (fractional, negative, non-numeric) and pass 0 through to `eng::simulate`.
- **Should-fix** (small) (`oracle_sim.rs:120, 143, 338`): `s["id"].as_str().unwrap_or_default()` turns a missing or numeric `id` into the empty label `""` silently. No oracle case has a numeric id, so it hides nothing today, but a default label is exactly the kind of quiet mapping the adapter must not do. Smallest fix: `ok_or_else(|| invalid("id must be a string"))`.
- Structural, note only: `unknown option {key}`, `error_model is missing`, `omega_shape is missing` are refused by the adapter because `SimInput` is a typed struct with no place for them. The engine cannot see an unknown option name until the future `sim.run` deserialises `SimInput`; `#[serde(deny_unknown_fields)]` on `SimInput` would then make it the engine's refusal.

## 5. The decisions taken meanwhile

1. **`Study::for_draws` skips the time checks — should-fix.** `for_draws` (`study.rs:114-116`) is `pub`, returns a full `Study`, and `Study::cell` and `Study::simulate` are `pub`. A Rust caller can therefore run `Study::for_draws(&input)?.simulate()` on a design with repeated or backwards times and obtain tables and a dataset that the dataset reader refuses (`duplicate_times`, DAT-ORD-01), which breaks the SIM-OUT-02 guarantee that every simulated table is a valid dataset. No command reaches it today (the adapter uses it for `exact` only), but the L0 API allows it. Smallest fix: a `draws_only: bool` set by `for_draws`, and `cell`/`cell_at`/`simulate` return `invalid_option` when it is set; and keep the `time_not_increasing` check in `for_draws` too, since the `tie_at_*` cases only need `duplicate_times` lifted (`study.rs:706`: filter the duplicate branch only).
2. No digest step: sound, see section 6.
3. Seed as a JSON number must be an integer in [0, 2^53-1]: `input.rs:32-47` and the `Deserialize` visitor (`input.rs:78-86`, a u64 above 2^53 is rounded to f64 and then refused by the bound, so no large integer slips through). Matches SIM-RNG-02.
4. `replicates` 0 is `invalid_option`, above 2^24 is `size_limit`: matches SIM-REF-03 and -06; R = 2^24 exactly is accepted, as "R ≤ 2²⁴" says.
5. The adapter's option allow-list: fine, see section 4.
6. The CLI dev-dependency: accepted by the orchestrator; it is the only way to put a thread test in `apps/` (`sim_threads.rs` is the caller SIM-DET-01 describes).

**Should-fix** (`input.rs:252, 266, 268`): `omega_shape`, `replicates` and `negative` carry no `#[serde(default)]`, while SIM-MOD-03 says `diagonal` is the default shape, SIM-MOD-05 says `replicates` defaults to 1 and `negative` to `keep`. The adapter fills them so the oracle does not see it, but the first `sim.run` that deserialises `SimInput` from command parameters will refuse a call the spec accepts. Smallest fix: `#[serde(default)]` on the three fields with `impl Default for OmegaShape { Diagonal }` and a `fn one() -> u64 { 1 }` default for `replicates`.

## Notes without a fix asked

- `rng.rs:104-110`: `Stream::new` is `pub` and ORs `replicate` into the low 24 bits without masking; a caller passing ≥ 2^24 would corrupt the purpose field. `Study::cell` and the adapter both guard it; a `debug_assert!` or a `& 0x00FF_FFFF` would make the type honest.
- `result.rs:195-231` with a pre-dose design: the dataset writes the dose row first and then an observation at an earlier time, exactly as SIM-OUT-02 says ("the dose row of the design, then one observation row per row"), but DAT-ORD-01 says rows of a subject must be in non-decreasing time and are never re-sorted, so the reader would refuse such a table with `time_not_increasing`, contradicting SIM-OUT-02's promise that every simulated table is a valid dataset. The engine followed the spec's sentence; the conflict is the spec's and goes to Abdou (write the dose row at its place in time order, or state that pre-dose designs produce a table the fit must sort explicitly).
- `result.rs:272`: `rng` is set to `philox4x32-10/as241/v1` in every result, but no oracle check reads it (grepped `sim_check.rs`); a one-line assertion in the study check would guard SIM-DET-03's version string.
- The pinned hash depends on Rust's float `Debug` formatting staying shortest-round-trip; it has been for years, but a toolchain change there would move the hash without a numeric change. The spec's "shortest round-trip decimal" is what is implemented.
